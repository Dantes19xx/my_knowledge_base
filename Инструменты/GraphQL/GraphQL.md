## Что такое GraphQL?

**GraphQL** — это язык запросов к API и среда выполнения этих запросов, разработанная Facebook в 2012 году и опубликованная в 2015. Он предоставляет альтернативу REST API с более гибким и декларативным подходом к получению данных.

---

## Ключевые особенности

|Особенность|Описание|
|---|---|
|**Декларативность**|Клиент сам указывает, какие поля и данные ему нужны.|
|**Единая точка входа**|Все данные доступны через один эндпоинт (`/graphql`).|
|**Типизация**|Все данные описываются с помощью строгой схемы типов.|
|**Без избыточности**|Получаешь ровно те данные, которые запросил — не больше, не меньше.|
|**Реактивность**|Возможность использования `Subscriptions` для получения обновлений в реальном времени.|

---

## Основные понятия

### Schema (Схема)

Определяет, какие типы данных доступны и как их можно запрашивать.

```graphql
type User {
  id: ID!
  name: String!
  email: String!
}

type Query {
  user(id: ID!): User
}
```

### Query (Запрос)

Запрос данных с указанием нужных полей:

```graphql
query {
  user(id: "1") {
    name
    email
  }
}
```

### Mutation (Мутация)

Для изменения данных (аналог POST/PUT/DELETE):

```graphql
mutation {
  createUser(name: "Alex", email: "alex@example.com") {
    id
    name
  }
}
```

### Subscription (Подписка)

Для получения данных в реальном времени (через WebSocket):

```graphql
subscription {
  userCreated {
    id
    name
  }
}
```

## Преимущества перед REST

- 🔁 Один запрос вместо нескольких (нет необходимости делать отдельные запросы к `/users`, `/posts`, `/comments`).
    
- ⚙️ Эволюция API без версии (добавление новых полей не ломает старые клиенты).
    
- 📦 Меньше данных в ответе — только то, что запросил клиент.
    

---

## Недостатки и вызовы

- Повышенная сложность на бэкенде (особенно в кэшировании и контроле доступа).
    
- Требует глубокого понимания схемы для эффективной работы.
    
- Проблемы с **N+1 запросами** без DataLoader или аналогичных решений.
    
- Не всегда подходит для простых CRUD-приложений.
    

---

## Где используется

- Facebook, GitHub, Shopify, Twitter, Pinterest, Airbnb, и др.
    
- Хорошо подходит для микросервисов, SPA, мобильных приложений.
    

---

## Когда выбирать GraphQL

**Подходит:**

- Когда фронтенду нужно больше контроля над данными.
    
- Когда API работает с разнородными источниками (микросервисы, БД, сторонние API).
    
- Когда требуется высокая гибкость и быстрое развитие интерфейсов.
    

**Не подходит:**

- В простых CRUD-приложениях с минимальными требованиями к фронтенду.
    
- Когда нужны строго определённые и кэшируемые HTTP-ответы (например, через CDN).

## Примеры инструментов

- **Apollo Server/Client** — один из самых популярных серверов и клиентов для GraphQL.
    
- **GraphQL Playground / GraphiQL** — IDE для написания и тестирования запросов.
    
- **Hasura** — instant GraphQL API поверх PostgreSQL.
    
- **Relay** — клиент от Facebook для более строгой архитектуры.
