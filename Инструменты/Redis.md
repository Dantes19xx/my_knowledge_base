# Redis — высокопроизводительное хранилище данных в памяти

✏️ **Redis** (REmote DIctionary Server) — это быстрый, открытый, in-memory хранилище структурированных данных с возможностью постоянства. Используется как **кеш**, **база данных**, **брокер сообщений**, **очередь задач** и многое другое.

---

## 🚀 Основные особенности Redis

|Характеристика|Описание|
|---|---|
|**In-memory**|Все данные хранятся в оперативной памяти, что обеспечивает высокую скорость|
|**Структуры данных**|Строки, списки, множества, упорядоченные множества, хэши, битмапы, гиперлоглоги, стримы|
|**Постоянство данных**|Поддержка snapshot-файлов (RDB) и append-only файлов (AOF)|
|**Кеширование**|Часто используется как кеш с политиками LRU, LFU, TTL|
|**Репликация**|Поддерживает master-slave репликацию|
|**Кластеризация**|Возможность горизонтального масштабирования|
|**Pub/Sub**|Поддержка publish/subscribe для создания реактивных систем|
|**Lua-скрипты**|Возможность выполнения скриптов на сервере|
|**Atomic operations**|Все команды Redis — атомарные|

---

## 🔧 Основные типы данных

|Тип|Пример использования|
|---|---|
|**String**|Кеш HTML-страниц, счетчики|
|**List**|Очереди задач|
|**Set**|Уникальные элементы (например, ID пользователей)|
|**Sorted Set**|Лидерборды, приоритизация элементов|
|**Hash**|Представление объектов (например, пользовательские профили)|
|**Stream**|Хранение событий и логов|

---

## 💾 Постоянство (Persistence)

Redis поддерживает два механизма сохранения данных на диск:

|Механизм|Описание|
|---|---|
|**RDB**|Snapshot базы через заданные интервалы|
|**AOF**|Запись каждой операции в лог, возможен более точный откат|

Можно использовать оба одновременно для надежности.

## ♻️ Репликация и кластеризация

### 🧭 [[Репликация и кеширование|Репликация]]:

- Один **master** и один или несколько **slaves**
    
- Используется для масштабирования на чтение и отказоустойчивости
    

### 📦 Кластер Redis:

- Разделяет данные между **шардами** (узлами)
    
- Каждый шард может иметь **master + replicas**
    
- Кластер масштабируется горизонтально и обеспечивает высокую доступность

## 🔒 Expiration и политики вытеснения

Можно задавать **TTL (Time-To-Live)** для ключей:

bash

CopyEdit

`SET session:123 "data" EX 60`

Redis поддерживает разные политики вытеснения:

- `noeviction` — ничего не удаляется (по умолчанию)
    
- `allkeys-lru` — удаляет наименее используемые ключи
    
- `volatile-lru` — удаляет наименее используемые из ключей с TTL
    
- и другие (`LFU`, `TTL`, `random`)

## 📡 Использование Redis

Примеры команд:

```bash
SET key "value"           # Установить значение
GET key                   # Получить значение
DEL key                   # Удалить ключ
EXPIRE key 60             # Установить TTL
INCR counter              # Увеличить счётчик
LPUSH queue "task"        # Добавить в список
BRPOP queue 0             # Получить и удалить последний элемент списка (блокирующе)
PUBLISH news "Hello!"     # Отправить сообщение в канал
SUBSCRIBE news            # Подписка на канал
```
