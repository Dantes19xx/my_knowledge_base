# Patroni — управление кластером PostgreSQL с высокой доступностью

**Patroni** — это инструмент для управления кластерами PostgreSQL, обеспечивающий **высокую доступность (High Availability, HA)** за счёт автоматического фейловера, репликации и координации между узлами.

---

## Основные возможности

- Автоматический **failover** при отказе основного узла
- Поддержка **репликации PostgreSQL**
- Использование внешнего хранилища (etcd, Consul, Zookeeper) для хранения метаданных о кластере
- REST API для управления и мониторинга
- Интеграция с **HAProxy** или другим прокси для маршрутизации запросов к активному лидеру

---

## Архитектура Patroni-кластера

```plaintext
           +-------------+
           |   HAProxy   | ← перенаправляет трафик к лидеру
           +------+------+
                  |
   +--------------+------------------+
   |              |                  |
+--+--+        +--+--+           +---+---+
|Node1|        |Node2|           |Node3  |
| PG  |        | PG  |           | PG    |
| Ptn |        | Ptn |           | Ptn   |
+--+--+        +--+--+           +---+---+
   |              |                  |
   +---------+----+------------------+
             |
      +------v------+
      | etcd/Consul |
      +-------------+
```


- **PG** — PostgreSQL
    
- **Ptn** — Patroni
    
- **etcd/Consul/Zookeeper** — внешнее распределённое хранилище состояния
    

---

## Как работает

1. Один из узлов становится **лидером** (primary).
    
2. Остальные — **реплики** (standby), синхронизируют данные.
    
3. Состояние кластера хранится в etcd/Consul.
    
4. При сбое лидера:
    
    - запускается **голосование** среди доступных узлов,
        
    - новый лидер автоматически выбирается и принимает трафик.

## Преимущества Patroni

- Простота в развертывании и настройке
    
- Гибкость и расширяемость
    
- Поддержка кастомных сценариев [[Фейловер-стратегии системы|фейловера]]
    
- REST API и автоматизация через инструменты вроде Ansible, Docker, [[Kubernetes]]

## Типичный стек с Patroni

| Компонент          | Назначение                                   |
| ------------------ | -------------------------------------------- |
| PostgreSQL         | СУБД                                         |
| Patroni            | Управление кластером и фейловер              |
| etcd/[[Consul]]    | Хранилище состояний и координации            |
| HAProxy            | Прокси, направляющий трафик на активный узел |
| SystemD/[[Docker]] | Средства развертывания                       |

---

## Когда использовать

- Необходима **высокая доступность PostgreSQL**
    
- Требуется **автоматический фейловер**
    
- Используются **кластерные/облачные среды**
    
- Нужна поддержка **масштабируемой репликации**
