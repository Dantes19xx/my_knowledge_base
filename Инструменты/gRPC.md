**gRPC** — это современный фреймворк удалённого вызова процедур (RPC), разработанный Google. Позволяет приложениям вызывать методы удалённого сервиса как локальные функции, используя HTTP/2 и Protocol Buffers.

---

## 📌 Общие сведения

| Характеристика        | Описание                                                                 |
|------------------------|--------------------------------------------------------------------------|
| **Полное название**    | gRPC = g(oogle) Remote Procedure Call                                    |
| **Протокол передачи**  | HTTP/2                                                                   |
| **Сериализация**       | Protocol Buffers (protobuf) — бинарный формат                            |
| **Языки**              | Python, Go, Java, C++, Rust и др.                                       |
| **Ключевые возможности** | Контракты через `.proto`, стриминг, двусторонняя передача, безопасность  |

---

## ⚙️ Принцип работы

1. Опиши API в `.proto`-файле.
2. Сгенерируй серверный и клиентский код из `.proto`.
3. Реализуй бизнес-логику на сервере.
4. Клиент вызывает методы как обычные функции — передача происходит по сети.

## 🧰 Когда использовать gRPC

- Микросервисная архитектура.
    
- Высокая нагрузка и требования к производительности.
    
- Коммуникация между сервисами на разных языках.
    
- Минимизация трафика за счёт бинарной сериализации.
    

---

## ✅ Преимущества

- Высокая производительность (HTTP/2 + protobuf).
    
- Явный контракт API.
    
- Поддержка стриминга и асинхронности.
    
- Кросс-языковая поддержка.
    

---

## ⚠️ Недостатки

- Кривая обучения выше, чем у REST.
    
- Сложности с дебагом (бинарный формат).
    
- Требует компиляции `.proto` файлов.
