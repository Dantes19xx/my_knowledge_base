### Виртуальные машины

**Виртуальные машины (ВМ)** — это изолированные экземпляры операционных систем, работающие поверх гипервизора. Они используют ресурсы физического сервера, но каждое приложение запускается в своей полноценной ОС.

**Плюсы:**

- Полная изоляция окружений.
    
- Возможность запускать разные ОС.
    
- Безопасность за счёт разделения ресурсов.
    

**Минусы:**

- Большой размер образов.
    
- Долгое время запуска.
    
- Дублирование ресурсов (ядра ОС, драйверов и т.д.).
    

---

### Контейнеры

**Контейнеризация** — это способ упаковки приложения и его зависимостей в единый, лёгкий, переносимый и изолированный контейнер.

Контейнеры используют ядро хостовой ОС и изолируют процессы с помощью Linux namespace и cgroups. Это позволяет:

- запускать контейнеры почти мгновенно,
    
- экономить ресурсы,
    
- масштабировать приложения быстро.
    

---

## Сравнение ВМ и Контейнеров

|Характеристика|Виртуальные машины|Контейнеры|
|---|---|---|
|Изоляция|На уровне ОС|На уровне процессов|
|Время запуска|Минуты|Секунды|
|Размер|ГБ|МБ|
|Потребление ресурсов|Высокое|Низкое|
|ОС в образе|Полноценная|Нет, только зависимости|

## Docker

**[[Docker]]** — это наиболее популярная платформа для работы с контейнерами. Она предоставляет средства для сборки, запуска и управления контейнерами.

---

### Dockerfile

`Dockerfile` — это набор инструкций, описывающих, как собрать образ.

**Пример простого Dockerfile:**

```Dockerfile
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
CMD ["python", "main.py"]
```

### Основные шаги при работе с Docker

1. **Создание Dockerfile**
    
2. **Сборка образа**  
    `docker build -t myapp .`
    
3. **Запуск контейнера**  
    `docker run -p 8000:8000 myapp`
    
4. **Управление контейнерами и образами**  
    `docker ps`, `docker images`, `docker stop`, `docker rm`, `docker rmi`
    

---

### Слои образа

Каждая инструкция в `Dockerfile` создает **новый слой**. Слои кешируются, что ускоряет пересборку.

**Пример:**
```Dockerfile
RUN apt-get update
RUN apt-get install -y curl
RUN curl https://example.com
```

Здесь три `RUN` — значит, будет три слоя. Это увеличивает размер образа.

### Оптимизация образов

Чтобы уменьшить размер образа:

- Объединяй команды:

```Dockerfile
RUN apt-get update && apt-get install -y curl
```

- Используй `.dockerignore`, чтобы не копировать ненужные файлы.
    
- Используй базовые образы с минимальным размером (`alpine`, `slim`).


---
### Пример оптимизированного Dockerfile

```Dockerfile
FROM python:3.11-slim

# Установка зависимостей в одном слое
RUN apt-get update && \
    apt-get install -y gcc && \
    apt-get clean && \
    rm -rf /var/lib/apt/lists/*

WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .
CMD ["python", "main.py"]
```
