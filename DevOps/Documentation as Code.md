# Documentation as Code

## Что это такое

**Documentation as Code (Docs-as-Code)** — это подход к созданию и сопровождению документации с использованием тех же инструментов, процессов и практик, что и в разработке программного обеспечения.

Документация становится частью репозитория с исходным кодом, и её разработка строится на принципах CI/CD, контроля версий, code review и автоматического тестирования.

---

## Ключевые принципы

| Принцип                  | Описание                                                                 |
|--------------------------|--------------------------------------------------------------------------|
| **Контроль версий**       | Документация хранится в системах контроля версий (например, Git).        |
| **Формат как код**        | Используются текстовые форматы: Markdown, AsciiDoc, reStructuredText.   |
| **Процессы CI/CD**        | Проверка орфографии, сборка и публикация документации через CI/CD.       |
| **Code review**           | Документация проходит ревью так же, как и код.                           |
| **Единый рабочий процесс**| Документация пишется вместе с кодом, в том же репозитории.              |
| **Автоматизация**         | Генерация API-документации, проверка линтером, тестирование ссылок.     |

---

## Преимущества

- 🔁 Согласованность между кодом и документацией
- ✅ Единый процесс ревью и правок
- 🧪 Возможность автоматизированного тестирования
- 🔧 Лёгкость интеграции в DevOps-процессы
- 💻 Удобство для технических специалистов (вся работа — в IDE и Git)

---

## Недостатки

- 📘 Менее удобно для не-технических авторов
- ⚙️ Требует настройки инфраструктуры (CI/CD, генераторы, проверки)
- 🧠 Требует от команды базового знания Git/Markdown и т.п.

---

## Инструменты

| Категория        | Примеры инструментов                      |
|------------------|-------------------------------------------|
| **Языки разметки** | Markdown, AsciiDoc, reStructuredText      |
| **Генераторы**     | MkDocs, Docusaurus, Sphinx, Hugo         |
| **CI/CD**         | GitHub Actions, GitLab CI, Jenkins        |
| **Проверки**      | Vale, markdownlint, link checker          |

---

## Подход в реальности

- 📂 Документация размещается рядом с кодом:
/project-root  
├── src/  
├── docs/  
│ ├── index.md  
│ ├── getting-started.md  
└── mkdocs.yml

- 🧾 Изменения вносятся через Pull Request и ревью.
- 🔁 Автоматическая сборка и деплой на каждый коммит.

---

## Когда использовать

- Внутренние и технические проекты
- Документация API, DevOps процессов, архитектуры
- Команды, активно использующие [[CI CD и создание конвейера|CI/CD]] и Git
- Когда важно обеспечить точность, версионность и непрерывность документации
