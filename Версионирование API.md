# Версионирование API: Semantic Versioning (SemVer)

Semantic Versioning (Семантическое версионирование) — это система обозначения версий, состоящая из трёх чисел: `Major.Minor.Patch`.

Допустим, версия вашего API — `2.0.0`. Вот что означает каждая часть:

## 1. **Major** (Основная версия) — `2`
Изменяется, когда вы вносите **обратимо несовместимые изменения**, например:
- Удаление или переименование полей
- Изменение поведения существующих эндпоинтов

Переход от `2.0.0` к `3.0.0` требует изменений со стороны разработчиков, использующих API.

## 2. **Minor** (Минорная версия) — `0`
Изменяется при **добавлении новых возможностей**, которые **совместимы с предыдущей версией**, например:
- Добавление нового эндпоинта
- Добавление необязательного поля

Переход от `2.0.0` к `2.1.0` предоставляет новые функции без необходимости менять существующий код.

## 3. **Patch** (Патч) — `0`
Изменяется при **исправлении ошибок и мелких улучшениях**, которые:
- Не добавляют новые функции
- Не нарушают обратную совместимость

Переход от `2.1.0` к `2.1.1` безопасен для всех пользователей.

---

## Пример структуры версий

| Версия | Изменения                     | Требует изменений у клиента |
|--------|-------------------------------|------------------------------|
| 2.0.0  | Основной релиз                | Да                           |
| 2.1.0  | Новые функции                 | Нет                          |
| 2.1.1  | Исправления и улучшения       | Нет                          |

## Полезно помнить
- Используйте `v` перед номером версии, например: `v2.1.0`
- Документируйте изменения в changelog
- Следите за совместимостью при выпуске Minor и Patch
