#data_engineering 

## 📘 Что это

**Data Vault** — это архитектурный подход к построению хранилищ данных, разработанный **Дэном Линстедом (Dan Linstedt)**. Модель предназначена для гибкого и масштабируемого хранения **исторических, интегрированных и изменяющихся данных**.

Главная цель — **соединить преимущества моделей [[Модель Инмона|Инмона]] и [[Модель Кимбалла|Кимбалла]]**, сохранив при этом:
- устойчивость к изменениям источников данных,
- полную историю,
- автоматизируемую структуру.

---

## 🧱 Основные компоненты

Data Vault построен на трёх типах сущностей:

| Компонент | Описание |
|-----------|----------|
| **Hub**   | Хранит **бизнес-ключи** (например, номер клиента, номер заказа). Один на каждую сущность. |
| **Link**  | Связи между Hub'ами. Отражают отношения (например, клиент оформил заказ). |
| **Satellite** | Атрибуты и история изменений для Hub или Link. Содержит метаданные и временные метки. |


---

## 🔍 Особенности модели

| Признак                   | Описание                                                                 |
|---------------------------|--------------------------------------------------------------------------|
| **Гибкость**              | Хорошо адаптируется к изменениям в источниках                            |
| **Историчность**          | Сохраняется вся история изменений (не перезаписываются данные)           |
| **Автоматизация**         | Можно автоматизировать генерацию моделей и ETL                           |
| **Масштабируемость**      | Легко масштабируется при росте данных и источников                       |
| **Задержка аналитики**    | Требует дополнительной трансформации для аналитического использования     |

---

## ✅ Преимущества

- Подходит для систем с **частыми изменениями бизнес-правил**
- **Масштабируется** в условиях большого количества источников
- **Отслеживает каждое изменение** (аудит, traceability)
- Является основой для **Data Lakehouse-архитектур**

---

## ❌ Недостатки

- Сложная логическая структура — **много таблиц**
- Для аналитики требуется **дополнительный слой витрин**
- **Неудобна напрямую для BI** — нужна трансформация в витрины (звезда/снежинка)
