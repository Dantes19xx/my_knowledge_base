# CDC (Change Data Capture)

## Что такое CDC?

**CDC (Change Data Capture)** — это техника, которая отслеживает и фиксирует изменения в данных базы данных (вставки, обновления, удаления) и передаёт их в другие системы или процессы в реальном времени или с минимальной задержкой.

Цель CDC — **обеспечить поток изменений** без необходимости полного чтения таблиц или периодических полных выгрузок.

---

## Зачем используется?

- **Репликация данных**
- **Обновление витрин данных (Data Warehouses)**
- **Интеграция микросервисов**
- **Событийная архитектура**
- **Снижение нагрузки по сравнению с периодическими выгрузками**

---

## Подходы к реализации CDC

| Метод | Описание |
|-------|----------|
| **Триггеры** | Использование триггеров в БД для записи изменений в отдельную таблицу |
| **Журналы транзакций (Log-based)** | Анализ бинарного лога (например, binlog в MySQL) для получения изменений |
| **Снапшоты и сравнение** | Сравнение текущего состояния с предыдущим (наименее эффективный метод) |
| **Встроенные возможности СУБД** | Некоторые СУБД (PostgreSQL, SQL Server) поддерживают CDC нативно |

---

## Примеры инструментов

- **Debezium** — популярный open-source CDC-инструмент, работает с Kafka
- **AWS DMS** — служба миграции данных с поддержкой CDC
- **SQL Server CDC** — встроенная поддержка в Microsoft SQL Server
- **Oracle GoldenGate** — коммерческое решение для CDC
- **Striim, Talend, HVR** — другие CDC-решения

---

## Пример: лог-базированный CDC

1. Изменение происходит в MySQL
2. Debezium читает binlog и формирует событие (insert/update/delete)
3. Событие отправляется в Apache Kafka
4. Консьюмер обрабатывает событие (обновляет витрину, вызывает API и т.д.)

---

## Преимущества

- Почти **реальное время**
- **Масштабируемость**
- **Минимальная нагрузка** на источник данных

---

## Недостатки

- Сложность настройки (особенно лог-базированный подход)
- Возможные проблемы с согласованностью
- Безопасность (доступ к журналам)

---

## Когда использовать CDC?

- Когда нужно **реплицировать данные в реальном времени**
- При построении **[[ETL]]/[[ELT]] пайплайнов**
- В **[[Event-Driven Architecture (EDA)|событийно-ориентированной архитектуре]]**
