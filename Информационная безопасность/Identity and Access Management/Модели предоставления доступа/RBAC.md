#ИБ

✏️ Role-Based Access Control (RBAC) — модель разделения доступов к данным на основе ролей.

В этой модели нужно определить, какие разрешения есть у пользователя, то есть какие действия в системе ему доступны. Дальше из этих разрешений нужно собрать роль.

Представьте, что роль — это лукошко, где лежат разные разрешения. Когда надо авторизовать пользователя на какое-либо действие, нужно посмотреть на его роль: есть ли в лукошке нужное разрешение.

**Архитектура RBAC**

RBAC состоит из таких сущностей:

- Subject — субъект, к которому применяется модель.
- Role — название роли пользователя, для которой определяется уровень доступа.
- Permissions — действия, которые выполняет пользователь в системе.
- Session — состояние, в рамках которого действует разрешение.

### RBAC Policy для системы управления заказами

Вот какие разрешения можно сформулировать:

- VIEW_ALL_ORDERS: просмотр всех заказов,
- VIEW_OWN_ORDERS: просмотр своих заказов,
- CREATE_ORDER: создание заказа,
- DELETE_ORDER: удаление заказа,
- DELETE_OWN_ORDER: удаление своего заказа,
- VIEW_DELETED_ORDER: просмотр удалённых заказов
