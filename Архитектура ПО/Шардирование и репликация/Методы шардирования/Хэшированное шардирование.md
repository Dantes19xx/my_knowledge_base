## 📌 Определение
**Хэшированное [[Шардирование|шардирование]]** — это метод распределения данных по шардам, при котором ключ шардирования пропускается через хэш-функцию. Результат этой функции определяет, в какой шард попадёт запись.

---

## ⚙️ Механизм работы

1. Выбирается поле (шард-ключ), по которому будет производиться шардирование, например, `user_id`.
2. Значение этого поля передаётся в хэш-функцию (например, MD5, SHA-256 или встроенную хэш-функцию СУБД).
3. Полученный хэш преобразуется в числовое значение.
4. Это значение сопоставляется с диапазоном одного из шардов.

---

## 🗂️ Пример

Допустим, у нас 4 шарда: `shard0`, `shard1`, `shard2`, `shard3`.

- Шард-ключ: `user_id = 123456`
- Хэш-функция: `hash(123456) = 738291`
- Определение шарда: `738291 % 4 = 3`
- Данные попадут в `shard3`

---

## ✅ Преимущества

- 🔄 **Равномерное распределение данных** — минимизирует горячие шарды.
- 📈 Хорошо масштабируется при большом количестве записей.
- 🔐 Снижает риск атак, основанных на предсказуемости ключей.

---

## ❌ Недостатки

- 🔍 **Плохая поддержка диапазонных запросов** — хэш разрушает естественный порядок данных.
- ⚙️ **Сложность пересборки шардинга** — при добавлении шардов требуется перераспределение данных (ребалансировка).
- ❗ Сложнее отлаживать и администрировать — хэш-ключи неинтуитивны.

---

## 🧠 Когда использовать

- Когда нужно **равномерно распределить данные** с непредсказуемыми значениями ключей.
- Когда **диапазонные запросы не приоритетны**.
- В высоконагруженных системах с **высокой скоростью записи и большим объёмом данных**.

---

## 📎 Примечание
MongoDB использует хэшированное шардирование с типом ключа:  
```json
{ "user_id": "hashed" }
```

## 🔚 Вывод

Хэшированное шардирование — мощный инструмент для равномерного распределения данных между шардами. Однако его следует использовать там, где не требуется выполнение большого количества диапазонных запросов.
