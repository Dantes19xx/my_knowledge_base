
# 🌍 Географическое шардирование

## 📌 Определение
**Географическое [[Шардирование|шардирование]]** — это стратегия размещения данных на шардах, ориентированная на **географическое расположение пользователей или клиентов**. Каждый шард обслуживает конкретный регион или страну, что позволяет повысить производительность и соответствие требованиям по хранению данных (compliance).

---

## ⚙️ Механизм работы

1. Определяется поле, связанное с регионом (например, `region`, `country_code`, `location_id`).
2. Каждому региону или группе регионов сопоставляется шард.
3. Все операции с данными пользователей из региона направляются в соответствующий шард.

---

## 🗂️ Пример

Предположим, у нас 3 шарда:

- `shard0`: обслуживает регион **Europe**
- `shard1`: обслуживает регион **North America**
- `shard2`: обслуживает регион **Asia**

Пользователь из Японии (`region = Asia`) будет храниться в `shard2`.

---

## ✅ Преимущества

- ⚡ **Минимизация задержек** — данные ближе к пользователю.
- 🛡️ **Соответствие законам и стандартам** — можно хранить данные в соответствии с требованиями (например, GDPR).
- ⚙️ **Логическая изоляция регионов** — проще управлять, обновлять, масштабировать отдельно.

---

## ❌ Недостатки

- 🧭 **Сложность балансировки** — регионы могут иметь разную нагрузку.
- 🔁 **Трудности с перекрёстными запросами** — сложно агрегировать данные из разных регионов.
- 🧩 **Усложнение архитектуры** — требуется географически распределённая инфраструктура.

---

## 🧠 Когда использовать

- При обслуживании **глобальных пользователей**.
- При наличии **юридических ограничений** на хранение данных.
- Когда нужно **минимизировать latency** для пользователей из разных стран.

---

## 📎 Примечание

MongoDB позволяет использовать **zone-based sharding** — шардирование с привязкой к тегам:

```json
{ "country_code": 1 }
```
