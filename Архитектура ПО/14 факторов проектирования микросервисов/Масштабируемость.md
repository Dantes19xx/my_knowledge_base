# Масштабируемость

## Определение

Масштабируемость — это способность системы **увеличивать пропускную способность** и **поддерживать стабильную производительность** при росте нагрузки.

## Цели

- Обеспечить стабильную работу при росте пользователей и данных
- Оптимально использовать ресурсы
- Гибко реагировать на всплески трафика
- Снижать затраты при снижении нагрузки

---

## Виды масштабирования

### 1. Горизонтальное масштабирование (Horizontal Scaling)

- Увеличение количества экземпляров (нод, контейнеров) одного и того же сервиса.

**Плюсы:**
- Эластичность
- Простота автоматизации
- Высокая отказоустойчивость

**Минусы:**
- Необходимость внешнего хранилища состояния
- Требует балансировки нагрузки

---

### 2. Вертикальное масштабирование (Vertical Scaling)

- Увеличение ресурсов (CPU, RAM) одного экземпляра.

**Плюсы:**
- Не требует изменения архитектуры
- Простой способ масштабирования небольших сервисов

**Минусы:**
- Жёсткие лимиты по железу
- Точка отказа

## Практики и паттерны

### [[Stateful & Stateless|Stateless]]-дизайн

- Без локального состояния: всё хранится во внешних хранилищах (кеш, база, очередь).
- Упрощает масштабирование по горизонтали.

---

### Автоматическое масштабирование (Auto Scaling)

- Использование метрик нагрузки (CPU, очередь сообщений, количество запросов) для автоматического масштабирования.

**Примеры:** Kubernetes HPA/VPA, AWS ASG, Azure VM Scale Sets

---

### Шардирование и репликация

- Разделение хранилищ данных на независимые фрагменты (shards)
- Репликация для отказоустойчивости и масштабирования чтения

---

### Разделение нагрузки

- Использование очередей (event-driven, async)
- Отложенная обработка (batch jobs, background workers)

## Метрики и мониторинг

- CPU и память
- Latency (время ответа)
- Количество активных соединений
- Очереди сообщений
- Количество запросов в секунду (RPS/QPS)

---

## Вывод

Масштабируемость — это не просто про «больше машин». Это **архитектурное свойство**, которое требует:
- ясного разграничения ответственности сервисов,
- проектирования без состояния,
- автоматизации инфраструктуры и
- продуманного распределения нагрузки.
