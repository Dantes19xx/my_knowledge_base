# 🧱 Архитектурный паттерн: API Gateway

## Описание

**API Gateway** — это сервер, являющийся единой точкой входа в микросервисную систему. Он управляет входящими запросами клиентов, маршрутизируя их к соответствующим микросервисам, выполняя аутентификацию, агрегацию данных и преобразование протоколов при необходимости. Используется для сокрытия внутренней архитектуры, централизованного управления и упрощения клиентской логики.

---

## Цели и задачи
- Централизация входа в систему.
- Обеспечение безопасности через аутентификацию/авторизацию.
- Упрощение клиентского взаимодействия.
- Агрегация данных от разных микросервисов.
- Кэширование, rate-limiting, логирование и мониторинг.

---

## Типовые функции API Gateway

| Функция                          | Описание                                                                        |
| -------------------------------- | ------------------------------------------------------------------------------- |
| **Маршрутизация**                | Перенаправление запроса к нужному микросервису на основе URL или других правил. |
| **Агрегация**                    | Объединение данных от нескольких микросервисов в один ответ.                    |
| **Аутентификация / Авторизация** | Проверка токенов (JWT, OAuth2 и пр.), доступов.                                 |
| **Преобразование протоколов**    | REST → [[gRPC]], WebSocket и др.                                                |
| **Кэширование**                  | Хранение ответов для повторных запросов.                                        |
| **Rate Limiting**                | Ограничение количества запросов от клиента.                                     |
| **Мониторинг / Логирование**     | Сбор статистики и логов о трафике.                                              |

---

## Преимущества
- Сокрытие внутренней логики и структуры системы.
- Централизованная безопасность и контроль доступа.
- Упрощение клиентов.
- Гибкость в эволюции микросервисов без изменения клиента.
- Возможность гибко внедрять кросс-сервисные функции.

---

## Недостатки
- Возможная точка отказа (если не масштабировать горизонтально).
- Задержка при агрегации данных.
- Усложнение инфраструктуры и конфигурации.
- Требует защиты самого шлюза (например, от DDoS).

## Когда использовать
- В микросервисной архитектуре с большим числом сервисов.
- Когда необходимо централизованно управлять кросс-сервисной логикой.
- При наличии разнообразных клиентов (веб, мобильные, IoT).
- Когда есть требования по безопасности и логированию на уровне API.

---

## Примеры использования
1. **E-commerce**: агрегировать данные заказов, товаров и рекомендаций в одном API-ответе для фронтенда.
2. **Мобильное приложение**: клиент делает один запрос — gateway рассылает его в 3 микросервиса и возвращает агрегированный ответ.
3. **SaaS-платформа**: gateway управляет доступом клиентов к нужным API с ограничениями по тарифу (rate limiting).

---

## Практические советы
- Используй JWT или OAuth2 для авторизации.
- Добавляй кэширование для неизменяемых данных (например, справочники).
- Разверни gateway с поддержкой масштабирования (k8s + ingress, autoscaling).
- Настраивай мониторинг ([[Prometheus]], [[Grafana]], [[OpenTelemetry]]).
