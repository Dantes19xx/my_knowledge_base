## Инфраструктурные паттерны микросервисной архитектуры

Инфраструктурные паттерны обеспечивают стабильность, безопасность, мониторинг и сопровождение микросервисной системы. Они не связаны напрямую с бизнес-логикой, но критически важны в проде.

---

### 1. Distributed Tracing

| Характеристика | Описание                                                   |
| -------------- | ---------------------------------------------------------- |
| Назначение     | Отслеживание цепочки вызовов между сервисами.              |
| Пример         | `frontend → api-gateway → auth-service → profile-service`. |
| Инструменты    | [[OpenTelemetry]], [[Jaeger]], Zipkin, AWS X-Ray.          |
| Плюсы          | Помогает выявлять узкие места, упрощает отладку.           |
| Минусы         | Сложность внедрения и визуализации.                        |

---

### 2. Audit Logging

| Характеристика       | Описание |
|----------------------|----------|
| Назначение           | Фиксация всех значимых действий в системе. |
| Пример               | Создание/удаление пользователя, изменение прав доступа. |
| Инструменты          | ELK Stack, Loki, S3, SQL. |
| Плюсы                | Повышает безопасность и соответствие требованиям. |
| Минусы               | Объём, конфиденциальность, правовое хранение. |

---

### 3. Centralized Logging

| Характеристика | Описание                                                                  |
| -------------- | ------------------------------------------------------------------------- |
| Назначение     | Сбор и просмотр логов всех сервисов в одном месте.                        |
| Пример         | Логи из всех подов Kubernetes поступают в Elasticsearch через Fluent Bit. |
| Инструменты    | [[ELK]], EFK, Loki, Graylog.                                              |
| Плюсы          | Быстрый поиск и анализ, централизованный контроль.                        |
| Минусы         | Задержки доставки, нагрузка на сеть и хранение.                           |

---

### 4. Metrics & Monitoring

| Характеристика | Описание                                                           |
| -------------- | ------------------------------------------------------------------ |
| Назначение     | Сбор количественных показателей и визуализация состояния сервисов. |
| Пример         | Запросы в секунду, ошибки, загрузка CPU.                           |
| Инструменты    | [[Prometheus]], [[Grafana]], Datadog.                              |
| Плюсы          | Контроль SLA, автоматические алерты.                               |
| Минусы         | Требует настройки и интерпретации.                                 |

---

### 5. Secrets Management

| Характеристика       | Описание |
|----------------------|----------|
| Назначение           | Безопасное хранение и управление секретами: токены, пароли, ключи. |
| Пример               | Доступ к БД через Vault, KMS или Kubernetes Secrets. |
| Инструменты          | HashiCorp Vault, AWS Secrets Manager, Doppler. |
| Плюсы                | Безопасность, централизованное управление. |
| Минусы               | Повышенная ответственность за безопасность хранилища. |
