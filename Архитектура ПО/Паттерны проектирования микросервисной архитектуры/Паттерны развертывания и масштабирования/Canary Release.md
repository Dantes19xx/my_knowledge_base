**Canary Release** (или **Canary Deployment**) — это паттерн пошагового развертывания, при котором **новая версия приложения выкатывается сначала на ограниченную долю пользователей**, а затем — постепенно на остальных.

Название происходит от практики шахтёров брать с собой канареек: если в шахте появлялся опасный газ, канарейка погибала первой — это позволяло избежать катастрофы. Аналогично, в IT-канареечный релиз позволяет **обнаружить проблемы на ранней стадии**, прежде чем они затронут всех пользователей.

---

## Как работает

1. Новая версия развёрнута параллельно с текущей.
    
2. Небольшая часть трафика направляется на новую версию (например, 5–10%).
    
3. Проводится наблюдение за метриками, логами, ошибками.
    
4. При успехе доля трафика увеличивается (например, 25%, затем 50%, и т.д.).
    
5. После полной уверенности, трафик полностью перенаправляется на новую версию.
    
6. Старая версия отключается.

## Подходы к распределению трафика

- По процентам (5% → 25% → 50% → 100%)
    
- По пользователям (например, по ID)
    
- По географии, региону
    
- По времени (например, 1 час наблюдения между этапами)
    

## Преимущества

- **Малый риск**: ошибки влияют только на часть пользователей
    
- **Быстрый откат**: можно немедленно отключить canary
    
- **Гибкий контроль**: можно собирать данные в процессе
    
- **Тестирование в реальных условиях**: без необходимости полного релиза
    

## Недостатки

- Усложнение маршрутизации трафика
    
- Нужна автоматизация и мониторинг
    
- Возможно непоследовательное поведение для разных пользователей
    
- Требует обратимых миграций базы данных


---

## Заключение

**Canary Release** — это гибкая и безопасная стратегия для развертывания новой версии приложения на продакшене с **поэтапным контролем и возможностью быстрого отката**. Подходит для систем, где важно качество, пользовательский опыт и стабильность.
