## Паттерны развертывания и масштабирования микросервисов

Эти паттерны обеспечивают безопасную доставку новых версий и масштабирование компонентов без простоя.

---

### 1. Service Discovery

| Характеристика       | Описание |
|----------------------|----------|
| Суть                 | Автоматическое обнаружение сервисов в распределённой системе. |
| Пример               | `order-service` регистрируется в Consul или Eureka, и другие сервисы находят его по имени. |
| Когда применять      | В динамической среде, например, Kubernetes. |
| Плюсы                | Упрощает масштабирование и отказоустойчивость. |
| Минусы               | Требует дополнительной инфраструктуры. |

---

### 2. Blue-Green Deployment

| Характеристика       | Описание |
|----------------------|----------|
| Суть                 | Две идентичные среды (Blue и Green); трафик переключается с одной на другую при релизе. |
| Пример               | Blue — текущая версия, Green — новая; после проверки Green становится активной. |
| Когда применять      | Когда важны минимальные простои и быстрое откатывание. |
| Плюсы                | Безопасный деплой, быстрый rollback. |
| Минусы               | Удвоение инфраструктуры. |

---

### 3. Canary Release

| Характеристика       | Описание |
|----------------------|----------|
| Суть                 | Новая версия выкатывается на небольшую часть трафика. |
| Пример               | 5% пользователей получают новую версию, затем процент увеличивается. |
| Когда применять      | Для постепенного внедрения и выявления проблем на раннем этапе. |
| Плюсы                | Контролируемый запуск, снижение рисков. |
| Минусы               | Сложность маршрутизации трафика и мониторинга. |

---

### 4. Sidecar

| Характеристика       | Описание |
|----------------------|----------|
| Суть                 | Вспомогательный контейнер запускается рядом с основным сервисом. |
| Пример               | Envoy или Istio в sidecar-контейнере для логгирования, мониторинга, TLS. |
| Когда применять      | При использовании сервисной mesh-архитектуры. |
| Плюсы                | Повторное использование логики, отделение ответственности. |
| Минусы               | Усложнение деплоймента и конфигурации. |

---

### Сравнение

| Паттерн             | Назначение                  | Плюсы                       | Минусы                    |
|---------------------|-----------------------------|-----------------------------|---------------------------|
| Service Discovery    | Динамическая маршрутизация  | Масштабируемость, гибкость | Требует инфраструктуры    |
| Blue-Green Deployment| Безопасное обновление       | Быстрый rollback            | Затраты на ресурсы        |
| Canary Release       | Плавное внедрение           | Минимизация рисков          | Сложная маршрутизация     |
| Sidecar              | Повторное использование функций | Чистая архитектура      | Усложнение сопровождения |
