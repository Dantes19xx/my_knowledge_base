## Паттерны разбиения микросервисов

Разбиение — ключевой этап проектирования микросервисной архитектуры. Грамотное деление системы на сервисы позволяет достичь масштабируемости, гибкости и упрощает сопровождение.

### 1. Разбиение по бизнес-возможностям (Business Capability)

| Характеристика       | Описание |
|----------------------|----------|
| Суть                 | Каждый микросервис соответствует отдельной бизнес-функции. |
| Пример               | Отдельные сервисы для: "Управление пользователями", "Платежи", "Каталог товаров". |
| Когда применять      | При наличии чётко выраженных бизнес-направлений. |
| Плюсы                | Хорошее соответствие организационной структуре, легко масштабировать. |
| Минусы               | Требуется тесное взаимодействие с бизнес-экспертами. |

---

### 2. Разбиение по поддоменам (Subdomain decomposition, DDD)

| Характеристика       | Описание |
|----------------------|----------|
| Суть                 | Разделение по поддоменам с использованием принципов Domain-Driven Design. |
| Пример               | В системе заказов: поддомены "Создание заказа", "Оплата", "Доставка". |
| Когда применять      | При сложной предметной области и использовании DDD. |
| Плюсы                | Глубокая проработка логики, слабая связность между сервисами. |
| Минусы               | Высокая сложность, требует хорошего знания предметной области. |

---

### Сравнение

| Критерий            | Business Capability         | Subdomain (DDD)            |
|---------------------|-----------------------------|-----------------------------|
| Уровень абстракции  | Более высокий                | Более детальный             |
| Требования к бизнесу| Средние                      | Высокие                     |
| Подходит для        | Типовых бизнес-приложений    | Сложных доменов с множеством связей |
