**Service Mesh** — это инфраструктурный паттерн, обеспечивающий **управление сетевыми коммуникациями между микросервисами**. Он реализуется через **дополнительный слой (mesh)**, отвечающий за маршрутизацию, балансировку, безопасность, мониторинг и отказоустойчивость трафика **без изменений в коде приложений**.

## Зачем нужен

В микросервисной архитектуре коммуникации между сервисами происходят по сети. При росте числа сервисов:

- становится сложно централизованно контролировать трафик,
    
- трудно обеспечить безопасность и шифрование,
    
- сложно отлаживать и мониторить взаимодействие.
    

**Service Mesh** позволяет решать эти задачи единообразно и прозрачно для разработчиков.

## Основные функции

1. **Маршрутизация трафика**
    
    - Канареечные и A/B-релизы
        
    - Управление версиями API
        
    - Перенаправление и фильтрация трафика
        
2. **Наблюдаемость**
    
    - [[Подходы к мониторингу|Метрики]] (latency, error rate)
        
    - [[Подходы к логированию|Логирование запросов]]
        
    - [[Distributed Tracing]]
        
3. **Безопасность**
    
    - TLS между сервисами (mTLS)
        
    - Аутентификация и авторизация
        
    - Политики доступа (RBAC)
        
4. **Отказоустойчивость**
    
    - [[Retry|Ретраи]]
        
    - [[Timeout|Таймауты]]
        
    - [[Circuit Breaker]]

## Архитектура

Service Mesh состоит из двух основных компонентов:

|Компонент|Назначение|
|---|---|
|**Data Plane**|Отвечает за обработку трафика. Представлен прокси-сервисами (sidecar), которые работают рядом с каждым микросервисом.|
|**Control Plane**|Централизованное управление политиками, конфигурацией и мониторингом.|

## Популярные реализации

| Инструмент         | Control Plane         | Data Plane (Proxy) | Особенности                                                        |
| ------------------ | --------------------- | ------------------ | ------------------------------------------------------------------ |
| **Istio**          | Istiod                | Envoy              | Полнофункциональный mesh с поддержкой mTLS, tracing, маршрутизации |
| **Linkerd**        | Linkerd control plane | Linkerd proxy      | Легковесный, простая установка, ориентирован на производительность |
| **Consul Connect** | [[Consul]]            | Envoy / native     | Интеграция с Consul Service Discovery                              |
| **Kuma**           | Kuma CP               | Envoy              | Поддерживается Kong, кросс-платформенность                         |

## Заключение

Service Mesh — это мощный инфраструктурный паттерн, необходимый для:

- безопасного и управляемого взаимодействия между микросервисами,
    
- построения отказоустойчивых распределённых систем,
    
- реализации централизованных политик без модификации приложений.
    

Его внедрение особенно оправдано при большом количестве сервисов и высоких требованиях к безопасности и надёжности.
