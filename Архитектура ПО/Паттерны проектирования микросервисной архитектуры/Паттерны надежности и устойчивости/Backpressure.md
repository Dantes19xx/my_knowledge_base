**Backpressure** (обратное давление) — это паттерн управления потоком данных между производителем и потребителем. Он необходим, когда производитель генерирует данные быстрее, чем потребитель может их обработать.

## Проблема

Если не контролировать поток:
- возможна утечка памяти,
- рост времени отклика,
- потеря данных,
- отказ системы.

## Цель Backpressure

Установить механизм, который:
- регулирует объем передаваемых данных,
- позволяет потребителю «сигнализировать» о своей перегрузке,
- помогает системе оставаться устойчивой под нагрузкой.

## Подходы к реализации

| Подход       | Описание                                              |
|--------------|--------------------------------------------------------|
| Drop         | Новые данные отбрасываются, если потребитель не успевает |
| Buffer       | Временное хранение данных в очереди (ограничено по размеру) |
| Block/Pause  | Производитель временно приостанавливается              |
| Batch/Throttle | Объединение данных в пакеты или ограничение скорости |

## Примеры в технологиях

| Технология                | Реализация Backpressure                                         |
| ------------------------- | --------------------------------------------------------------- |
| RxJava / Reactive Streams | Интерфейс `Flowable`, методы `request(n)`                       |
| Akka Streams              | Pull-модель потока, потребитель управляет темпом данных         |
| Kafka                     | Настройки `max.poll.records`, `fetch.min.bytes`, `consumer lag` |
| [[gRPC]] / HTTP/2         | Контроль потока через window size                               |
| TCP                       | Sliding window и ACK-механизм на уровне протокола               |

## Когда применять

Backpressure важен в следующих случаях:

- Потоковые системы (Kafka, Spark Streaming, Flink)
    
- Асинхронные микросервисы
    
- Реактивные фреймворки (RxJava, Spring WebFlux, Project Reactor)
    
- Сетевые протоколы и API-шлюзы
    

## В контексте реактивной архитектуры

Backpressure поддерживает ключевые свойства реактивных систем:

- **Responsiveness** — система остаётся отзывчивой
    
- **Resilience** — система выдерживает сбои и перегрузки
    
- **Elasticity** — система масштабируется в зависимости от нагрузки
