## Паттерны интеграции микросервисов

Интеграционные паттерны определяют, как микросервисы обмениваются данными — синхронно через API или асинхронно через события.

---

### 1. API Gateway

| Характеристика       | Описание |
|----------------------|----------|
| Суть                 | Центральная точка входа, маршрутизирующая запросы к нужным микросервисам. |
| Пример               | NGINX, Zuul, Kong, AWS API Gateway. |
| Когда применять      | Когда клиентам нужно взаимодействовать с множеством сервисов. |
| Плюсы                | Централизованная аутентификация, агрегация ответов, защита. |
| Минусы               | Единая точка отказа, требует дополнительной настройки. |

---

### 2. Backend for Frontend (BFF)

| Характеристика       | Описание |
|----------------------|----------|
| Суть                 | Создание отдельных API для разных типов клиентов (Web, Mobile). |
| Пример               | Отдельный BFF-сервис для мобильного приложения. |
| Когда применять      | Когда клиентам нужны разные представления/объёмы данных. |
| Плюсы                | Оптимизация под конкретного клиента, уменьшение объема данных. |
| Минусы               | Увеличение количества сервисов, сложность поддержки. |

---

### 3. Событийная шина (Event Bus)

| Характеристика       | Описание |
|----------------------|----------|
| Суть                 | Асинхронное взаимодействие через публикацию и подписку на события. |
| Пример               | Kafka, RabbitMQ, NATS. |
| Когда применять      | При слабой связности и необходимости масштабируемой коммуникации. |
| Плюсы                | Высокая масштабируемость, низкая связанность сервисов. |
| Минусы               | Сложность отладки, необходимость в мониторинге событий. |

---

### Сравнение

| Критерий            | API Gateway           | BFF                    | Event Bus                |
|---------------------|-----------------------|------------------------|--------------------------|
| Тип связи           | Синхронный            | Синхронный             | Асинхронный              |
| Уровень связанности | Средний               | Средний                | Низкий                   |
| Использование       | Общий API             | Клиент-ориентированный | Событийная архитектура   |
| Плюсы               | Централизация         | Оптимизация под клиента| Масштабируемость         |
| Минусы              | Точка отказа          | Рост числа API         | Сложность отладки        |
