# Domain-Driven Design (DDD)

**DDD (Domain-Driven Design)** — это подход к разработке программного обеспечения, при котором основное внимание уделяется предметной области и логике бизнеса. Его предложил Эрик Эванс в одноимённой книге.

---

## Основные принципы DDD

| Принцип | Описание |
|--------|----------|
| **Модель предметной области (Domain Model)** | Центральное место занимает бизнес-логика, отражённая через объекты и их поведение. |
| **Ubiquitous Language (Единый язык)** | Общий язык между разработчиками и экспертами предметной области, основанный на терминах домена. |
| **Bounded Context (Ограниченный контекст)** | Чёткие границы, внутри которых используется единая модель и язык. |
| **Контекстные карты (Context Map)** | Отображение связей между различными ограниченными контекстами. |

---

## Структура модели DDD

| Компонент | Описание |
|-----------|----------|
| **Entity (Сущность)** | Объекты с уникальной идентичностью (например, `User`, `Order`). |
| **Value Object (Объект-значение)** | Объекты без идентичности, описывающие характеристики (например, `Money`, `Address`). |
| **Aggregate (Агрегат)** | Группа объектов, управляемая через корневую сущность (Aggregate Root). |
| **Repository** | Интерфейс для получения и сохранения агрегатов. |
| **Service (Доменный сервис)** | Операции, не подходящие ни одной сущности. |
| **Factory** | Создание сложных объектов и агрегатов. |
  

Когда применять DDD

- Сложные бизнес-домены
- Взаимодействие с экспертами предметной области
- Неоднородная система с разными моделями в разных частях


Когда избегать DDD


- Простые CRUD-приложения
- Быстрые MVP-прототипы
- Отсутствие доступа к экспертам предметной области
