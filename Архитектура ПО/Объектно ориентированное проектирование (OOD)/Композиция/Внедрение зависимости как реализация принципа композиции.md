## 📌 Суть

**Композиция** — это подход, при котором объект включает в себя другие объекты и делегирует им поведение, **не создавая их внутри**.  
В ООП это достигается через **внедрение зависимостей (Dependency Injection)**.

Это способствует:
- гибкости архитектуры;
- модульности;
- лёгкости тестирования;
- соблюдению принципов **[[SOLID-принципы|SOLID]]** (особенно **DIP** и **[[O — Open Closed Principle]]**).

---

## ✅ Хороший пример: внедрение зависимости через [[__init__]]

```python
class Logger:
    def log(self, message: str):
        print(f"[LOG] {message}")

class UserService:
    def __init__(self, logger: Logger):
        self.logger = logger

    def register_user(self, name: str):
        self.logger.log(f"User {name} registered")
```

### ✔ Преимущества:

- `UserService` **не зависит от конкретной реализации `Logger`**.
    
- Можно легко подменить `Logger` на `MockLogger` в тестах.
    
- Соблюдаются **OCP** (новые логгеры можно добавлять без изменения `UserService`) и **DIP**.

### ❌ Плохой пример (антипаттерн): жёсткая связность

```python
class UserService:
    def __init__(self):
        self.logger = Logger()  # ← создаём зависимость внутри

    def register_user(self, name: str):
        self.logger.log(f"User {name} registered")
```


### ✘ Проблемы:

- Жёсткая зависимость от `Logger`.
    
- Нельзя заменить реализацию без изменения кода `UserService`.
    
- Трудно писать тесты (нельзя внедрить заглушку).
    
- Нарушаются принципы **DIP** и **OCP**.


### 🧪 Использование в тестах

```python
class MockLogger:
    def log(self, message: str):
        print(f"[MOCK] {message}")

mock_logger = MockLogger()
service = UserService(mock_logger)
service.register_user("TestUser")
```


## 🧠 Вывод

Внедрение зависимости через конструктор — это реализация принципа **композиции**, которая:

- упрощает поддержку кода,
    
- делает систему гибкой к изменениям,
    
- позволяет легко писать тесты и расширять поведение.
    

> 💡 Принцип: **"Композиция предпочтительнее наследования"** — особенно при проектировании гибкой архитектуры.
