
#ood

**Композиция** — это способ построения объектов, при котором **один объект включает в себя другие объекты как поля** и **делегирует им часть поведения**.

> 📌 Принцип: "Собирай объекты из других объектов, а не наследуй поведение."

---

### 📦 Пример: без композиции (наследование)

```python
class Engine:
    def start(self):
        print("Engine started")

class Car(Engine):
    def drive(self):
        self.start()
        print("Car is driving")
```

Здесь `Car` наследует `Engine`. Но логически это **"имеет двигатель"**, а не **"есть двигатель"**.

### ✅ Композиция — правильный подход

```python
class Engine:
    def start(self):
        print("Engine started")

class Car:
    def __init__(self, engine: Engine):
        self.engine = engine

    def drive(self):
        self.engine.start()
        print("Car is driving")
```

Теперь `Car` **содержит** `Engine`, и **делегирует** ему запуск. Это композиция.

---

### 📌 Преимущества композиции:

|Преимущество|Описание|
|---|---|
|✅ Слабое зацепление|Компоненты можно менять без переписывания родителя|
|✅ Повторное использование|Один и тот же компонент (`Engine`) можно использовать в `Car`, `Boat`, `Plane`|
|✅ Гибкость|Можно подменять зависимости (напр. через DI)|
|✅ Лучше соблюдает OCP и SRP|Новое поведение — через расширение, а не изменение|

### 🧠 Наследование vs Композиция

| Характеристика | Наследование                   | Композиция                 |
| -------------- | ------------------------------ | -------------------------- |
| Отношение      | **"является"** (is-a)          | **"имеет"** (has-a)        |
| Связанность    | Сильно связано                 | Слабо связано              |
| Расширяемость  | Трудно расширять без изменений | Легко заменять и расширять |
| Гибкость       | Жёсткая иерархия               | Гибкая структура           |
| Риск           | Ломает инкапсуляцию родителя   | Изолирует поведение        |

### 🔄 Пример с Python и SOLID

**Принцип DIP (инверсия зависимостей)** можно легко реализовать через композицию:

```python
class Logger:
    def log(self, message):
        print(message)

class UserService:
    def __init__(self, logger: Logger):
        self.logger = logger

    def register_user(self, name):
        self.logger.log(f"User {name} registered")
```

Здесь `UserService` **не зависит от конкретной реализации логирования**. Это и есть **композиция + инверсия зависимостей**.

---

### 💬 Вывод:

**Композиция — мощный и гибкий способ проектирования**, особенно в больших системах. Она способствует:

- соблюдению **SOLID-принципов**;
    
- удобному **тестированию**;
    
- **расширяемости** и повторному использованию компонентов.
- Зависимость необходимо внедрять внутрь класса извне, предварительно создав инстанс. Делается это с помощью [[Внедрение зависимости как реализация принципа композиции|такого подхода]].
