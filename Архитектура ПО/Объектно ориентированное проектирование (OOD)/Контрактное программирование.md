#ood

**Контрактное программирование** (англ. _Design by Contract_, сокр. **DbC**) — это **методология проектирования программ**, при которой каждый компонент (функция, класс, модуль) работает в рамках **чётко определённого контракта**: набора **обязательств и гарантий** между ним и внешним миром (другими компонентами).

Эту концепцию ввёл **Бертран Мейер**, автор языка **Eiffel**.

---

## 📜 Суть контракта

Контракт включает три части:

|Часть контракта|Описание|
|---|---|
|**Предусловие (Precondition)**|Что **должно быть истинным до** вызова функции — требования к входным данным|
|**Постусловие (Postcondition)**|Что **будет истинным после** выполнения функции — гарантии результата|
|**Инвариант (Invariant)**|Что **должно оставаться истинным всегда** — внутри объекта или класса|

## 🧩 Пример на Python

```python
def divide(a, b):
    assert b != 0, "Divider must not be zero"        # предусловие
    result = a / b
    assert result * b == a                            # постусловие (упрощённое)
    return result
```

- Перед вызовом: вызывающая сторона должна **гарантировать**, что `b ≠ 0` (предусловие).
    
- После выполнения: функция **гарантирует**, что результат корректный (постусловие).
    

---

## 🧠 Контракт = Договор между компонентами

Программист говорит:

> "Если ты дашь мне входные данные, соответствующие предусловию, я гарантирую, что результат будет соответствовать постусловию. Всё, что между — моя забота."

---

## 📌 Пример в ООП (инвариант объекта)

```python
class BankAccount:
    def __init__(self, balance):
        assert balance >= 0        # инвариант
        self.balance = balance

    def withdraw(self, amount):
        assert amount > 0
        assert amount <= self.balance     # предусловие
        self.balance -= amount
        assert self.balance >= 0         # постусловие
```

---

## 🔍 Как это связано с [[SOLID-принципы|SOLID]] и LSP

- **[[L — Liskov Substitution Principle|LSP]] требует соблюдения контракта** при наследовании:  
    Подкласс **не должен ослаблять предусловия и не должен усиливать постусловия**.
    
- **DIP и [[O — Open Closed Principle|OCP]]** тоже выигрывают от контрактов:  
    Когда интерфейсы имеют чёткие контракты, их легко подменять и расширять.

## ✅ Преимущества:

- 📎 Чёткая документация поведения кода
    
- 🧪 Упрощённое тестирование
    
- 🧱 Повышение надёжности
    
- 🚦 Упрощение отладки (через `assert`)
    
- 🔧 Возможность автоматической проверки условий
    

---

## ❌ Минусы:

- Не реализован как встроенная фича в Python (только через `assert` или сторонние библиотеки)
    
- Часто требует дисциплины и шаблонов
    

---

## 🔧 Инструменты

- `assert` — простой способ реализации предусловий и постусловий.
    
- [`icontract`](https://github.com/Parquery/icontract) — библиотека для DbC в Python.
    
- Языки вроде Eiffel, Ada и D имеют встроенную поддержку контрактов.
