#solid

**Принцип открытости/закрытости**

> "Программные сущности должны быть **открыты для расширения**, но **закрыты для изменения**."  
> — Бертран Мейер

### 📌 Суть:

Ты должен писать код так, чтобы **добавлять новое поведение можно было без изменения уже существующего кода**.

🔧 Вместо того чтобы переписывать старые классы, ты добавляешь **новые расширения** — через наследование, интерфейсы, делегирование и т.п.

---

### 🧠 Зачем это нужно:

- Минимизировать риски: не ломаешь старый, протестированный код.
    
- Упростить поддержку: можно добавлять фичи без копания в основе.
    
- Повысить модульность: компоненты независимы и расширяемы.
    

---

### ❌ Нарушение OCP — плохой пример:

```python
class DiscountCalculator:
    def calculate(self, user_type, amount):
        if user_type == "regular":
            return amount
        elif user_type == "vip":
            return amount * 0.9
        elif user_type == "staff":
            return amount * 0.8
```

Каждый раз при добавлении нового типа пользователя нужно **лезть в метод** и **менять его** — это нарушает OCP.

### ✅ Соблюдение OCP — хороший пример:

```python
class DiscountStrategy:
    def calculate(self, amount):
        return amount

class VipDiscount(DiscountStrategy):
    def calculate(self, amount):
        return amount * 0.9

class StaffDiscount(DiscountStrategy):
    def calculate(self, amount):
        return amount * 0.8

# Использование
def apply_discount(strategy: DiscountStrategy, amount):
    return strategy.calculate(amount)
```


Теперь ты можешь:

- добавлять новые типы скидок (наследуя `DiscountStrategy`);
    
- **не трогать старый код**;
    
- покрывать каждую стратегию своими тестами.
    

---

### 🔧 Как соблюдается OCP на практике:

- **Наследование**: расширяй поведение через подклассы.
    
- **Интерфейсы/абстрактные классы**: реализуй конкретные варианты.
    
- **[[Композиция]] и делегирование**: заменяй поведение через внедрение зависимостей.
    
- **Паттерны**: Strategy, Decorator, State, Chain of Responsibility и др.
    

---

### 💬 Итого:

**Принцип OCP учит нас не переписывать существующее — а расширять поведение без риска.**  
Он делает систему **гибкой**, особенно когда требования часто меняются.
