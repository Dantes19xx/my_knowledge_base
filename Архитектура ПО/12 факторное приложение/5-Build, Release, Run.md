Приложение должно чётко разделять **три этапа жизненного цикла**:

- **Build (Сборка)** — компиляция зависимостей, подготовка артефактов;
    
- **Release (Релиз)** — связывание сборки с конфигурацией;
    
- **Run (Запуск)** — фактический запуск приложения в процессе.
    

Это обеспечивает предсказуемость и воспроизводимость развёртывания. Изменения кода, зависимостей и конфигурации управляются независимо.

|Этап|Описание|Пример команды / действия|
|---|---|---|
|Build|Сборка проекта, установка зависимостей|`pip install -r requirements.txt`|
|Release|Комбинирование сборки с переменными окружения|`export DATABASE_URL=... && tag v1.0-release`|
|Run|Запуск приложения в нужной среде|`python app.py`, `gunicorn app:app`, `docker run app:latest`|
#### 💡 Пример с Docker:

- **Build**: `docker build -t myapp .`
    
- **Release**: `docker tag myapp:latest myregistry/myapp:v1.0`
    
- **Run**: `docker run -e DATABASE_URL=... myapp:v1.0`
