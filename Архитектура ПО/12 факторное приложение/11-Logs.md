
## Logs — Логи

**Принцип:**  
Приложение не должно управлять логами самостоятельно — оно должно писать логи в стандартный вывод ([[stdout]]), а сбор и анализ должен выполняться внешними системами.

---

### Основные положения

| Аспект      | Описание                                                                           |
| ----------- | ---------------------------------------------------------------------------------- |
| Назначение  | Отделение сбора логов от приложения, облегчает масштабирование и отладку.          |
| Практика    | Писать логи в stdout/stderr, не создавать лог-файлы.                               |
| Инструменты | [[Logstash]], Fluentd, Promtail, [[Grafana]], [[Loki]], [[ELK]], systemd-journald. |
| Антипаттерн | Приложение пишет логи в файлы и управляет ротацией.                                |

---

### Примеры

**Python (стандартный вывод):**
```python
import logging
import sys

logging.basicConfig(stream=sys.stdout, level=logging.INFO)
logging.info("Service started")
```

---

**Примечание**

Логирование должно быть потоковым и обрабатываться внешними системами. Это позволяет централизованно отслеживать поведение приложения во всех средах.
