
## Суть
Приложение работает как один или несколько **статeless процессов**, не хранящих внутреннее состояние между запросами. Всё состояние должно храниться во внешних хранилищах (БД, кэш, файловые сервисы).

## Зачем это нужно
- Масштабируемость (горизонтальный скейлинг)
- Отказоустойчивость
- Предсказуемое поведение при перезапусках
- Простота деплоя и обновлений

## Что нельзя делать
- Использовать `global` переменные для хранения пользовательских данных
- Держать сессии в памяти процесса
- Хранить временные данные между запросами без внешнего хранилища

## Что нужно делать
- Хранить состояние в Redis, PostgreSQL, S3 и т.д.
- Использовать очереди (Celery + Redis/RabbitMQ)
- Делать каждый процесс перезапускаемым и независимым

## Примеры

### Плохо
```python
# Глобальное состояние — не работает при нескольких процессах
online_users = []

@app.post("/login")
def login(user: str):
    online_users.append(user)
    return {"status": "ok"}
```

Хорошо

```python

# Внешнее хранилище (Redis)
@app.post("/login")
def login(user: str, redis: Redis = Depends(get_redis)):
    redis.sadd("online_users", user)
    return {"status": "ok"}
```
