# Контекстная диаграмма (System Context Diagram)

Контекстная диаграмма — это **первый уровень нотации C4**, где система рассматривается как чёрный ящик. Главная цель — показать **взаимодействие системы с внешним миром**: пользователями и другими системами.

---

## 🎯 Назначение

- Пояснить **роль системы** в организации или в бизнес-процессе.
- Выявить **внешние зависимости**.
- Обеспечить общее понимание для **стейкхолдеров**, **менеджеров**, **разработчиков** и **архитекторов**.

---

## 📐 Что отображается на контекстной диаграмме?

### ✅ Система (в центре):
- Представляется как **один прямоугольник**.
- Содержит:
  - Название
  - Краткое описание
  - При желании — технологии (например, Web-приложение, API и т.д.)

### ✅ Пользователи (actors):
- Реальные люди или роли, которые взаимодействуют с системой (например, «Клиент», «Сотрудник поддержки»).

### ✅ Внешние системы:
- Другие приложения, с которыми происходит обмен данными (например, «Система CRM», «Платёжный шлюз», «Внутренний API банка»).

### ✅ Взаимодействия:
- Стрелки, указывающие направление связи.
- Можно указать протокол (HTTP, SOAP, Kafka и т.д.) или бизнес-функцию (например, «Запрос баланса»).

## 📊 Шаблон для создания контекстной диаграммы

```plaintext
+------------------+       HTTP       +---------------------+
| Пользователь     | <--------------> |     Система         |
| (например, Клиент)|                 | (Ваше приложение)   |
+------------------+                  +---------------------+
                                          |
                                          | REST API
                                          v
                                  +-------------------+
                                  | CRM / Внешняя СУБД |
                                  +-------------------+
```



---

## 🧠 Практические советы

- Используй **минимум элементов**, чтобы не перегрузить.
    
- Делай фокус на **роли пользователей и внешние интерфейсы**, а не на внутреннюю реализацию.
    
- Добавляй **короткие описания** для каждой сущности и взаимодействия.
    
- Применяй **единообразие** в цветах, размерах и подписи элементов.
    

---

## 🔧 Инструменты

- **Structurizr DSL**: `SystemContext` блок.
    
- **PlantUML (C4 extension)**:

```pl
!includeurl https://raw.githubusercontent.com/plantuml-stdlib/C4-PlantUML/master/C4_Context.puml

Person(client, "Клиент")
System(system, "Интернет-банк", "Обрабатывает запросы клиентов")
System(crm, "CRM", "Управление контактами")

Rel(client, system, "Пользуется", "HTTPS")
Rel(system, crm, "Запрашивает клиентские данные", "REST API")
```

## 📌 Когда использовать?

- В начале архитектурного ревью.
    
- При разработке **ADR-документов** (Architectural Decision Records).
    
- Для общения с **стейкхолдерами**, которые не вовлечены в детали архитектуры.
