# Диаграмма компонентов (Component Diagram)

Диаграмма компонентов — третий уровень в нотации C4. Этот уровень показывает, **из каких компонентов состоит один конкретный контейнер**. Здесь уже появляется структура кода, но на логическом уровне, без погружения в классы.

---

## 🎯 Назначение

- Показать **архитектуру одного контейнера**.
- Раскрыть **ключевые модули и их взаимодействие**.
- Упростить коммуникацию между разработчиками и архитекторами.

---

## 🧱 Что такое компонент?

Компонент — это:

- Крупный **логический блок**, реализующий значимую часть функциональности.
- Обычно соответствует **модулю**, **сервису**, **классу контроллеров** или **адаптеру**.
- Может быть REST-контроллер, сервис авторизации, репозиторий, бизнес-логика.

---

## 📐 Что отображается на диаграмме?

- **Контейнер**, который раскрывается.
- **Компоненты внутри контейнера**.
- **Взаимодействия между компонентами**.
- **Внешние зависимости**, с которыми работают компоненты (другие контейнеры, API, БД).
- **Технологии (по желанию)**.

---

## 📊 Пример диаграммы

```plaintext
Контейнер: Backend API (FastAPI)

+--------------------+     +---------------------+      +----------------+
| AuthController     | --> | AuthService         | ---> | UserRepository |
+--------------------+     +---------------------+      +----------------+
                               |                             |
                               v                             v
                       +------------------+         +--------------------+
                       | JWTProvider      |         | PostgreSQL         |
                       +------------------+         +--------------------+

```

```puml
Container(api, "Backend API", "Python + FastAPI", "Обрабатывает HTTP-запросы")

Component(authController, "AuthController", "FastAPI Router", "Обрабатывает логин")
Component(authService, "AuthService", "Python Service", "Бизнес-логика авторизации")
Component(userRepo, "UserRepository", "PostgreSQL", "Получает пользователей из БД")
Component(jwtProvider, "JWTProvider", "Python Module", "Генерирует токены")

Rel(authController, authService, "Вызывает")
Rel(authService, userRepo, "Получает данные")
Rel(authService, jwtProvider, "Генерирует токены")
```



---

## 🧠 Практические советы

- Выбирай **1 контейнер = 1 диаграмма компонентов**.
    
- Не уходи в низкоуровневые детали (классы, методы).
    
- Используй **осмысленные подписи и названия** компонентов.
    
- Показывай **архитектурные паттерны** (например, MVC, [[CQRS]], Ports and Adapters).
    
- Старайся показать **разделение ответственности**.
    

---

## 💡 Для каких случаев полезна?

- Обзор архитектуры backend-а / frontend-а.
    
- Передача знаний между командами.
    
- Архитектурные ревью и Code Walkthrough.
    
- Документация в ADR.

```puml
!includeurl https://raw.githubusercontent.com/plantuml-stdlib/C4-PlantUML/master/C4_Component.puml

Container(api, "Backend API", "Python")

Component(controller, "AuthController", "FastAPI", "Обработка логина")
Component(service, "AuthService", "Python", "Бизнес-логика")
Component(repo, "UserRepository", "PostgreSQL", "Хранение пользователей")

Rel(controller, service, "Вызывает")
Rel(service, repo, "Читает")
```
