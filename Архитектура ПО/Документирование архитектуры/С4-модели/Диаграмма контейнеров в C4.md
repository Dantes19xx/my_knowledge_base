# Диаграмма контейнеров (Container Diagram)

Диаграмма контейнеров — второй уровень модели C4. Она раскрывает, **из каких компонентов состоит система**, какие технологии используются и как происходит взаимодействие между частями приложения.

---

## 🎯 Назначение

- Показать **архитектуру системы как совокупности контейнеров** — развёртываемых исполняемых блоков.
- Продемонстрировать **взаимодействие между контейнерами**, пользователями и внешними системами.
- Помочь в **планировании масштабирования**, **разделения ответственности**, **разработки и тестирования**.

---

## 📦 Что такое контейнер?

Контейнер в C4 — **не Docker-контейнер**, а логическая единица, которую можно разворачивать и исполнять. Это может быть:

- Веб-приложение
- REST API
- База данных
- Очередь сообщений
- Микросервис
- UI SPA
- Внешний адаптер
- Мобильное приложение

---

## 📐 Что отображается на диаграмме?

- **Контейнеры системы**
- **Пользователи** (те же, что в контексте)
- **Внешние системы**
- **Взаимодействия между ними**
- **Технологии и порты** (опционально)

---

## 📊 Пример диаграммы

```plaintext
+------------+       +---------------------+
| Клиент     | <---> | Web-интерфейс (SPA) |
+------------+       +---------------------+
                          |
                          | REST API (HTTPS)
                          v
                  +--------------------+
                  | Backend-сервис     |
                  | (FastAPI / Flask)  |
                  +--------------------+
                          |
         +----------------+----------------+
         |                                 |
         v                                 v
+----------------+               +------------------+
| PostgreSQL     |               | Kafka            |
| (Хранение)     |               | (Асинхронка)     |
+----------------+               +------------------+
```

```puml
System_Boundary("InternetBankingSystem") {
  Container(spa, "Web SPA", "JavaScript", "Интерфейс клиента")
  Container(api, "Backend API", "Python + FastAPI", "Бизнес-логика")
  Container(db, "PostgreSQL", "Database", "Хранит пользовательские данные")
  Container(kafka, "Kafka", "Message Broker", "Обмен сообщениями")

  Person(client, "Клиент")
  System_Ext(crm, "CRM")

  Rel(client, spa, "Использует", "HTTPS")
  Rel(spa, api, "Вызывает API", "REST/JSON")
  Rel(api, db, "Сохраняет/читает данные", "SQL")
  Rel(api, kafka, "Публикует события", "Kafka")
  Rel(api, crm, "Запрашивает контактные данные", "REST")
}
```


---

## 🧠 Практические рекомендации

- Не перегружай: от 3 до 6 контейнеров — оптимально.
    
- Подписи к стрелкам должны **объяснять смысл взаимодействия** (например: «Читает список счетов»).
    
- Указывай **технологии**, если это важно для понимания (Python, Kafka, PostgreSQL).
    
- Контейнер — это **уровень между системой и компонентами**. Это как сервисы и базы, но без детализации кода.

## 🔧 Инструменты

- Structurizr DSL
    
- PlantUML с C4 расширением:

```puml
!includeurl https://raw.githubusercontent.com/plantuml-stdlib/C4-PlantUML/master/C4_Container.puml

Person(client, "Клиент")
System_Boundary(s1, "Интернет-банк") {
  Container(web, "Web SPA", "JavaScript", "Интерфейс")
  Container(api, "Backend API", "Python", "Бизнес-логика")
  Container(db, "PostgreSQL", "База данных")
}

Rel(client, web, "Пользуется")
Rel(web, api, "REST API")
Rel(api, db, "SQL")
```
