# ✅ Чеклист: Нужно ли внедрять трейсинг в компонент

## 🧩 Архитектура и роль компонента
- [ ] Компонент участвует в критически важных бизнес-цепочках (например, заказ, оплата, логистика)
- [ ] Компонент обменивается данными с другими сервисами (через HTTP, RMQ, Kafka и т.п.)
- [ ] Компонент обрабатывает асинхронные задачи (через очередь)
- [ ] Компонент вызывает внешние API (влияет на общее время ответа)

## 🔍 Требования к наблюдаемости
- [ ] Часто возникают инциденты, требующие анализа межсервисных связей
- [ ] Отладка по логам затруднена (например, не хватает trace-id для сквозной корреляции)
- [ ] Есть требования SLA / мониторинга по цепочке выполнения

## ⚠️ Ограничения и стоимость внедрения
- [ ] Есть ресурсы для внедрения и поддержки OTEL SDK и collector'а
- [ ] Производительность критична, но допустим overhead ~5-10%
- [ ] Нет других инструментов, уже решающих задачу (например, полные APM)

---

## 🟢 Рекомендации
- Если отмечено **≥5 пунктов** — **однозначно внедрять трейсинг**
- Если **3–4 пункта** — рассмотреть частичную интеграцию (например, только HTTP, без RMQ)
- Если **≤2 пункта** — достаточно логирования и метрик
