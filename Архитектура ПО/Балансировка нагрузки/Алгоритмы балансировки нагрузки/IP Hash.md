**IP Hash** — это алгоритм балансировки нагрузки, при котором выбор сервера основан на **хэшировании IP-адреса клиента**. Это позволяет одному и тому же клиенту **всегда попадать на один и тот же сервер** (если конфигурация не изменилась).


---
### Принцип работы

1. Балансировщик берёт IP-адрес клиента.
    
2. Вычисляется **хэш** (например, по формуле `hash(IP) % N`, где N — количество серверов).
    
3. Запрос направляется на сервер по индексу, полученному из хэша.
    
4. Для одного клиента — один и тот же сервер, пока конфигурация стабильна.

> [!NOTE]
> ## Пример
> 
> Сервера: [A, B, C]
> Клиент с IP 192.168.1.10
> 
> Хэш(192.168.1.10) % 3 = 1 → сервер B

Если клиент подключается повторно — он снова попадёт на сервер B.

---

### Преимущества

- **Стабильность сессий** — клиент всегда попадает на один сервер
    
- Удобно для **[[Stateful & Stateless|stateful]]-приложений** (например, когда нет общего хранилища сессий)
    
- Простая реализация


### Недостатки

- **Неравномерное распределение нагрузки** (одни IP могут "перегрузить" один сервер)
    
- Если **добавить или убрать сервер**, все хэши смещаются → клиенты будут перенаправлены на другие сервера (**потеря сессий**)
    
- Не подходит для балансировки по производительности


---


### Когда использовать

- Нужно сохранять **состояние сессии на сервере**
    
- Нет внешнего **хранилища сессий** (Redis, Memcached и т.д.)
    
- Требуется **простая** и быстрая маршрутизация


---

### Отличие от других алгоритмов

| Алгоритм                 | Основной критерий         |
| ------------------------ | ------------------------- |
| [[Round Robin]]          | Очередность               |
| [[Weighted Round Robin]] | Очередность + вес         |
| [[Least Connections]]    | Меньше всего соединений   |
| IP Hash                  | Хэш клиента (IP → сервер) |
