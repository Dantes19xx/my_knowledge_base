**Weighted Least Connections (WLC)** — это гибрид двух алгоритмов:

- **[[Least Connections]]** — направляет трафик на сервер с наименьшим числом активных соединений,
    
- **Weighted** — учитывает **вес** сервера (его мощность).
    

Балансировщик выбирает сервер, у которого **отношение активных соединений к весу минимально**.

---

### Принцип работы

1. Каждый сервер имеет вес (`weight`), отражающий его производительность.
    
2. Для каждого сервера вычисляется:
3. Запрос направляется на сервер с **наименьшей нагрузкой** по этой формуле. (*нагрузка = активные соединения / вес*)


---
### Преимущества

- Более **точная балансировка**, чем у обычного Least Connections
    
- Учитывает **производительность серверов**
    
- Лучше подходит для **гетерогенной среды** (разные сервера)

### Недостатки

- Требует точного указания весов
    
- Требует отслеживания соединений в реальном времени
    
- Сложнее в реализации по сравнению с базовыми алгоритмами


---

### Примеры применения

| Платформа / Инструмент | Поддержка WLC                         |
| ---------------------- | ------------------------------------- |
| **HAProxy**            | ✅ (через `balance leastconn` и веса)  |
| **NGINX**              | ❌ (нет нативной поддержки WLC)        |
| **Traefik / Envoy**    | ⚠️ Частично, через кастомные политики |

---

### Когда использовать

- Разные сервера с **разной производительностью**
    
- Запросы с **переменной длительностью**
    
- Нужна **точная адаптация под нагрузку** с учётом различий в железе


---

### Отличие от других алгоритмов

| Алгоритм                 | Основной критерий                    |
| ------------------------ | ------------------------------------ |
| [[Round Robin]]          | Очередность                          |
| [[Weighted Round Robin]] | Очередность с весами                 |
| [[Least Connections]]    | Меньше всего активных соединений     |
| **Weighted Least Conn.** | Меньшее значение: `соединения / вес` |
