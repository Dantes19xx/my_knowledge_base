Балансировщики нагрузки распределяют входящий трафик между несколькими серверами, чтобы обеспечить отказоустойчивость, масштабируемость и стабильную производительность.

---

### 🔁 Основные алгоритмы

| Алгоритм                           | Принцип                                                                     | Преимущества                                 | Недостатки                   |
| ---------------------------------- | --------------------------------------------------------------------------- | -------------------------------------------- | ---------------------------- |
| **[[Round Robin]]**                | Поочередная отправка запросов на сервера                                    | Простой                                      | Не учитывает загрузку        |
| **[[Weighted Round Robin]]**       | Как Round Robin, но с весами                                                | Балансировка с учётом мощностей              | Нужна ручная настройка весов |
| **[[Dynamic Round Robin]]**        | Как Weighted Round Robin но весы распределяются на основе собираемых метрик | Динамически расчитываемые весы               | Сложности реализации         |
| **[[Least Connections]]**          | Выбирается сервер с наименьшим числом соединений                            | Учитывает активность                         | Не учитывает ресурсы         |
| **[[Weighted Least Connections]]** | Учитываются соединения и вес сервера                                        | Баланс между нагрузкой и производительностью | Сложнее конфигурация         |
| **[[IP Hash]]**                    | Постоянное сопоставление IP клиента и сервера                               | Простая "стики-сессия"                       | Неравномерная нагрузка       |
| **[[Consistent Hashing]]**         | Используется хеш-кольцо                                                     | Устойчивость при изменении топологии         | Сложность реализации         |
| **Random**                         | Случайный выбор сервера                                                     | Простота                                     | Может быть неэффективным     |
| **Least Response Time**            | Сервер с минимальным временем ответа                                        | Реакция на перегрузку                        | Требует мониторинга          |
| **Custom (Rule-based)**            | Правила: гео, headers, версия API и т.д.                                    | Гибкость                                     | Сложность поддержки          |
| **Least Bandwidth**                | Сервер с наименьшим трафиком                                                |                                              |                              |

---

### 🏗️ Примеры использования

#### NGINX

```
upstream backend {
    server app1.example.com;
    server app2.example.com;
}

# Least Connections
upstream backend {
    least_conn;
    server app1.example.com;
    server app2.example.com;
}

```

#### HAProxy

```
backend web_servers
    balance roundrobin
    server app1 192.168.0.1:80 weight 3
    server app2 192.168.0.2:80 weight 1

```

### 📌 Выбор алгоритма по ситуации

| Сценарий                                      | Алгоритм                                |
| --------------------------------------------- | --------------------------------------- |
| Простая балансировка между идентичными узлами | Round Robin                             |
| Разные мощности серверов                      | Weighted Round Robin                    |
| Пользователи с "прилипанием" к серверу        | IP Hash                                 |
| Высокая нагрузка, важна скорость реакции      | Least Connections / Least Response Time |
| Микросервисы с динамическим масштабированием  | Consistent Hashing                      |
| Сложные правила, географическое распределение | Custom                                  |
