
Балансировка нагрузки — это метод распределения входящих запросов или трафика между несколькими серверами или сервисами для достижения **высокой доступности**, **отказоустойчивости** и **масштабируемости**.

---

## 🧱 1. По уровню модели OSI

| Уровень | Тип | Описание |
|--------|-----|----------|
| L4     | **Балансировка по TCP/UDP** | Работа с IP-адресами и портами, без знания о приложении. Быстрее, но менее гибко. |
| L7     | **Балансировка по HTTP/HTTPS** | Понимает содержимое запроса (URL, cookies, заголовки). Позволяет делать умную маршрутизацию. |

---

## ⚙️ 2. По методу реализации

| Тип                                                     | Описание                                           | Примеры                        |
| ------------------------------------------------------- | -------------------------------------------------- | ------------------------------ |
| **[[Программный балансировщик нагрузки\|Программная]]** | Выполняется на уровне ПО, как сервис или прокси.   | NGINX, HAProxy, Traefik, Envoy |
| **[[Аппаратные балансировщики нагрузки\|Аппаратная]]**  | Использует выделенные устройства для балансировки. | F5 Big-IP, Citrix ADC          |
| **Облачная (managed)**                                  | Предоставляется облачным провайдером как сервис.   | AWS ELB, GCP Load Balancer     |

---

## 🔁 3. По алгоритму распределения трафика

| Алгоритм                     | Описание                                              |
| ---------------------------- | ----------------------------------------------------- |
| **[[Round Robin]]**          | Циклическое распределение на каждый сервер по очереди |
| **[[Least Connections]]**    | Сервер с наименьшим количеством активных соединений   |
| **[[IP Hash]]**              | Один и тот же IP → один и тот же backend              |
| **[[Weighted Round Robin]]** | Серверы с разным "весом" получают разную долю трафика |
| **Random**                   | Выбор сервера случайным образом                       |
| **Response Time**            | С учётом скорости ответа от сервера                   |

---

## 🕸️ 4. По топологии размещения

| Тип | Описание |
|------|----------|
| **Reverse Proxy** | Балансировщик между клиентом и backend (наиболее распространённый) |
| **DNS-based** | Балансировка реализуется через DNS-записи |
| **Client-side** | Клиент сам выбирает сервер по внутренней логике или конфигурации |
| **Service Mesh (sidecar)** | Балансировка на уровне контейнеров/сервисов (например, Istio + Envoy) |

---

## 🧮 5. По цели балансировки

| Цель | Пример |
|------|--------|
| **HTTP-запросы** | Балансировка API или веб-приложений |
| **Базы данных** | Чтения с реплик, записи — на мастер |
| **Очереди сообщений** | Распределение задач между воркерами |
| **Сетевой трафик** | Балансировка TCP/UDP соединений |

---

## 📌 Вывод

Балансировка нагрузки классифицируется по:

- 🧱 Уровню сети (L4/L7)
- ⚙️ Типу реализации (программная, аппаратная, облачная)
- 🔁 Алгоритму маршрутизации
- 🕸️ Архитектуре размещения
- 🎯 Целевому назначению

Такой подход помогает выбрать подходящий балансировщик под конкретные требования инфраструктуры.
