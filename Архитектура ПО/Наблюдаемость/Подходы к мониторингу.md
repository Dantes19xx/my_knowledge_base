# 🧭 USE, RED, Четыре золотых сигнала

Эти подходы помогают систематически выбирать метрики, которые стоит отслеживать в продакшене.

---

## 🔧 USE (Utilization, Saturation, Errors)

**USE — Utilization, Saturation, Errors**  
Предложен Брэндоном Греггом (Brendan Gregg), подходит для мониторинга **низкоуровневых компонентов**: CPU, память, диск, сеть и т.п.

**Расшифровка:**

| Компонент     | Описание                                              | Пример метрик                     |
|---------------|-------------------------------------------------------|-----------------------------------|
| ⚙️ Utilization | Насколько активно используется ресурс                | CPU usage %, диск I/O %           |
| 🚧 Saturation  | Очереди или признаки перегрузки                      | Length of disk queue, run queue   |
| ❌ Errors      | Количество ошибок при использовании ресурса          | Ошибки чтения/записи, drop-пакеты |

**Применение:**
- Аппаратные ресурсы
- Сетевые интерфейсы
- Очереди в ОС и железе

**Инструменты:**
- Netdata
- Prometheus node_exporter
- Grafana dashboards

## 🛑 RED (Rate, Errors, Duration)

**RED — Rate, Errors, Duration**  
Подходит для **HTTP-сервисов и микросервисов**, ориентирован на производительность API.

**Расшифровка:**

| Компонент | Описание                            | Примеры                         |
|-----------|-------------------------------------|----------------------------------|
| 📈 Rate   | Кол-во запросов в секунду (RPS)     | `http_requests_total`           |
| ❌ Errors | Ошибки (5xx, 4xx)                    | `http_requests_errors_total`    |
| ⏱ Duration | Время отклика (latency)            | `http_request_duration_seconds` |

**Применение:**
- Микросервисы (REST, gRPC)
- API-шлюзы
- Backend-приложения

**Инструменты:**
- Prometheus + `http_server_requests_seconds_*`
- Grafana RED dashboard
- Istio, Envoy (метрики трафика)

## 🌟 Четыре золотых сигнала (The Four Golden Signals)

**Подход от Google SRE** — универсальный для мониторинга любой распределённой системы.

**Сигналы:**

| Сигнал       | Описание                                                 | Примеры метрик                       |
|--------------|----------------------------------------------------------|--------------------------------------|
| ⏱ Latency    | Время ответа                                             | 95/99 процентиль, p95/p99 latency    |
| ❌ Errors     | Доля ошибочных запросов                                 | 4xx, 5xx, тайм-ауты                  |
| 📈 Traffic    | Объём запросов или нагрузки                             | RPS, QPS, трафик в байтах            |
| 🚧 Saturation | Нагрузка и приближение к пределу ресурса                | CPU, RAM, очередь, соединения        |

**Применение:**
- Полный охват системы сверху донизу
- Подходит для SLO/SLI мониторинга
- Связан с философией SRE (Site Reliability Engineering)

**Инструменты:**
- Prometheus + Grafana
- Stackdriver (Google)
- Datadog / New Relic

## 🧱 Сравнительная таблица подходов

| Подход        | Назначение                   | На чём фокусируется                    | Где применим                       |
|---------------|------------------------------|----------------------------------------|------------------------------------|
| **USE**       | Низкоуровневый анализ        | Утилизация, перегрузка, ошибки         | Хосты, железо, сети                |
| **RED**       | Производительность API       | RPS, ошибки, латентность               | HTTP/gRPC сервисы                 |
| **4 сигнала** | Общий мониторинг сервисов    | Латентность, ошибки, трафик, насыщение | Любые распределённые системы      |

---

## 🧩 Комбинация подходов

Для полного охвата часто комбинируют:
- **RED** → для микросервисов
- **USE** → для серверов и инфраструктуры
- **4 сигнала** → в качестве базового фреймворка
