# Мониторинг, Логирование, Трейсинг

## 📊 Мониторинг (Metrics)

**Определение**:  
Мониторинг — это сбор и анализ числовых метрик, отражающих состояние системы и бизнес-процессов.

**Типы метрик**:

| Категория          | Примеры                                      |
|--------------------|-----------------------------------------------|
| 🧱 Инфраструктурные | CPU, RAM, диск, сеть, аптайм, кол-во запросов |
| ⚙️ Технические       | Время отклика API, ошибки 5xx, QPS            |
| 💼 Бизнесовые        | Доход, количество заказов, конверсии          |

**Зачем нужен**:
- Построение дашбордов
- Настройка алертов (оповещений)
- Анализ производительности

**Инструменты**:
- Prometheus + Grafana
- Datadog
- New Relic
- AWS CloudWatch

---

## 📚 Логирование (Logs)

**Определение**:  
Логирование — это запись текстовых сообщений, фиксирующих события и поведение системы.

**Ключевые особенности**:

| Параметр         | Значение                                                |
|------------------|---------------------------------------------------------|
| 📋 Уровни логов   | DEBUG, INFO, WARNING, ERROR, CRITICAL                  |
| 🧾 Формат         | Предпочтительно JSON (для машинной обработки)          |
| 🌍 Место хранения | stdout, файл, централизованные системы (Elasticsearch) |

**Зачем нужно**:
- Отладка и поиск багов
- Аудит действий
- Анализ ошибок

**Инструменты**:
- ELK Stack (Elasticsearch, Logstash, Kibana)
- Grafana Loki
- Fluentd / Fluent Bit
- Sentry (для ошибок)

---

## 🧭 Трейсинг (Traces)

**Определение**:  
Трейсинг — это отслеживание полного пути запроса через все сервисы и компоненты, фиксируя каждый шаг (span).

**Основные компоненты**:

| Компонент  | Описание                                                  |
|------------|-----------------------------------------------------------|
| 🧱 Trace    | Общий идентификатор для всей цепочки запроса             |
| 🔹 Span     | Отдельный шаг: HTTP-запрос, SQL-запрос, публикация в очередь |
| 🔗 Context | Передаётся между сервисами и связывает спаны в один трейс |

**Зачем нужен**:
- Диагностика задержек
- Поиск узких мест
- Понимание взаимосвязей между сервисами

**Инструменты**:
- Jaeger
- Zipkin
- OpenTelemetry
- Datadog APM

---

## 🧩 Сравнение: Метрики, Логи, Трейсы

| Характеристика     | Мониторинг         | Логирование        | Трейсинг                |
|--------------------|--------------------|---------------------|--------------------------|
| 📦 Тип данных       | Числовые метрики    | Текстовые события   | Структурированные спаны  |
| 🧠 Уровень абстракции | Высокоуровневый     | Событийный          | Пошаговый, контекстный   |
| 📈 Частота сбора    | Периодическая       | По факту события     | По факту запроса         |
| 🔍 Назначение        | Общее здоровье      | Отладка и анализ     | Производительность, трассировка |

---

## 🔧 Рекомендации

- Используй **структурированные логи** (например, JSON).
- Передавай **TraceID** в заголовках HTTP между микросервисами.
- Настрой алерты по ключевым метрикам (ошибки, отклик, нагрузка).
- Используй **OpenTelemetry** как единый стандарт сбора метрик, логов и трейсов.
