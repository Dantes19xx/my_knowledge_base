# 📜 Подходы к логированию

## 📤 stdout (12-Factor Style)

### 🧱 Суть подхода

В стиле **12-Factor App** рекомендуется, чтобы приложение **писало все логи в stdout/stderr**, а не в файлы или удалённые сервисы напрямую. Это делает приложение **безопасным, переносимым и облачно-готовым**.

> 📌 Приложение пишет лог, а не управляет им.

### ✅ Преимущества

| Преимущество                     | Описание                                                                                                      |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **Упрощение архитектуры**        | Приложение не заботится о лог-агрегации или ротации логов. Это задача окружения.                              |
| **Совместимость с контейнерами** | В [[Docker]], [[Kubernetes]] и других средах контейнеризации stdout/stderr легко собирается лог-агрегаторами. |
| **Гибкость обработки**           | Логи можно перенаправлять, фильтровать, агрегировать и пересылать без изменений в коде.                       |
| **Лёгкость локального отладки**  | Простота — всё выводится в консоль, доступно сразу.                                                           |

### 🔧 Реализация

#### Python (logging в stdout)

```python
import logging
import sys

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s [%(levelname)s] %(message)s",
    stream=sys.stdout
)

logging.info("Hello from stdout logger")
```

### 🔗 Интеграция с лог-агрегаторами

В современных облачных платформах и системах оркестрации логирование через stdout/stderr собирается:

|Платформа|Лог-сборщик|
|---|---|
|Docker|`docker logs`, Fluentd|
|Kubernetes|`kubectl logs`, Loki, Fluent Bit, EFK|
|AWS / GCP|CloudWatch Logs, Stackdriver|
|Heroku|Автоматически собирает stdout/stderr|

### ⚠️ Антипаттерны (чего избегать)

- ❌ Запись логов в локальные файлы из приложения (например, `/var/log/app.log`).
    
- ❌ Самостоятельное сжатие/ротация логов в коде.
    
- ❌ Жёсткая привязка к конкретной лог-системе (например, напрямую в Elasticsearch).
    

### 📌 Заключение

Логирование в stdout — **надежный, переносимый и масштабируемый** способ, который идеально вписывается в современные DevOps/Cloud-native практики. Всё, что пишет приложение, должно быть легко перехватываемо и агрегируемо **без изменения самого приложения**.

> Лог — это поток событий, а не база данных. Обработка и анализ — задача внешних инструментов.
