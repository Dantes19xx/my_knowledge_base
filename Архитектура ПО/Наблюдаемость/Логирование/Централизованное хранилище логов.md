## 4. 🗂 Централизованное хранилище логов

### 🧱 Суть подхода

**Централизованное лог-хранилище** — это единая система, в которую собираются все логи из различных приложений, серверов и сервисов. Обычно используется в связке с агентами (Fluent Bit, Filebeat и др.), которые доставляют логи в это хранилище.

> 📦 Все логи хранятся в одном месте, что позволяет осуществлять полнотекстовый поиск, корреляцию событий, мониторинг, алерты и аудит.

---

### ✅ Преимущества

| Преимущество | Описание |
|--------------|----------|
| **Поиск и фильтрация** | Быстрый поиск по всем логам (по полям, тегам, содержимому). |
| **Централизация** | Один интерфейс доступа к логам всех сервисов. |
| **Аналитика и визуализация** | Поддержка дашбордов, графиков, алертов. |
| **Хранение истории** | Возможность задать срок хранения (недели, месяцы). |
| **Аудит и безопасность** | Хранение неотредактируемых логов для расследований. |

---

### 🧩 Популярные системы хранения логов

| Название                                  | Характеристика                                               |
| ----------------------------------------- | ------------------------------------------------------------ |
| **[[Elasticsearch]]** (в составе ELK/EFK) | Мощный полнотекстовый поиск, [[Kibana]] — UI                 |
| **[[Grafana]] Loki**                      | Быстрая, лёгкая, ориентирована на контейнеры, без индексации |
| **AWS CloudWatch Logs**                   | Облачная, с IAM, алертами, интеграцией с AWS                 |
| **Google Cloud Logging**                  | Интеграция с GCP, мощный фильтр, алерты                      |
| **Splunk**                                | Enterprise-решение, дорогое, но мощное                       |
| **Datadog Logs**                          | SaaS с автоанализом, метриками, алертами                     |
| **Graylog**                               | Open-source, поддержка потоков, алертов, поисков             |

---

### 📦 Что в централизованном хранилище обычно есть

| Компонент | Назначение |
|-----------|------------|
| **Интерфейс поиска** | UI/веб-интерфейс с фильтрами и запросами |
| **API** | Программный доступ к логам |
| **Алерты и триггеры** | Настройка уведомлений по событиям в логах |
| **Дашборды** | Визуализация ключевых метрик и паттернов |
| **Политики хранения** | Установка TTL, архивирования и удаления |

---

### 🔧 Пример архитектуры

```text
[Приложения (stdout / файлы)]
         ↓
[Лог-агенты: Fluent Bit, Filebeat]
         ↓
[Централизованное хранилище: Elasticsearch / Loki / CloudWatch]
         ↓
[UI: Kibana, Grafana, Cloud Console]
```

### 📌 Примеры применения

| Сценарий                        | Реализация                                   |
| ------------------------------- | -------------------------------------------- |
| Анализ логов всех микросервисов | Loki + Promtail + Grafana                    |
| Хранение логов безопасности     | ELK с фильтрацией по событиям                |
| Облачный мониторинг             | CloudWatch + Lambda алерты                   |
| Аудит доступа и операций        | Graylog или Splunk с сохранением на 90+ дней |

---

### ⚠️ Сложности и риски

|Проблема|Решение|
|---|---|
|📈 Рост объёма логов|Фильтрация на агенте, сжатие, TTL|
|💸 Высокая стоимость|Использовать open-source (Loki, Graylog) или уменьшать ретеншн|
|📉 Потеря логов|Настроить буферы, ретраи, HA для агентов и хранилища|
|⚙️ Сложная настройка|Использовать Helm-чарты, Terraform-модули, SaaS|
|🔒 Безопасность|Аудит доступа, шифрование, IAM, ограничения на поиск|

---

### 🎯 Когда применять централизованное лог-хранилище

|Подходит когда|Обоснование|
|---|---|
|Много приложений/сервисов|Невозможно смотреть логи вручную или по ssh|
|Требуется анализ и алерты|Необходим UI и автопроверки|
|Хранение истории логов|Аудит, разбор инцидентов, отчётность|
|Нужна интеграция с метриками|Unified observability (логи + метрики + трассировки)|

---

> 🧠 Централизованное логирование — это не только инструмент для отладки, но и важная часть **SRE/DevOps культуры**. Оно помогает **предотвращать инциденты**, а не только расследовать их.
