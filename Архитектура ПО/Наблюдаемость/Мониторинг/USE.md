# 🔧 Подход USE в мониторинге

Подход **USE** (Utilization, Saturation, Errors) — это метод мониторинга, ориентированный на **инфраструктурный уровень** (CPU, память, диски, сеть). Он помогает системно выявлять узкие места в ресурсах и деградацию производительности оборудования.

## 🧱 Что такое USE?

| Компонент | Описание | Примеры метрик |
|-----------|----------|----------------|
| **Utilization** | Насколько активно используется ресурс (в процентах от полной загрузки). | `cpu_utilization`, `memory_used / memory_total`, `disk_io_utilization` |
| **Saturation** | Очерёдность или ожидание доступа к ресурсу. Показывает, что система перегружена. | `load_average`, `run_queue`, `iowait`, `network_queue_length` |
| **Errors** | Количество ошибок, связанных с ресурсом (например, сбои ввода-вывода, отказы интерфейсов). | `disk_errors_total`, `network_dropped_packets`, `cpu_throttling` |

## 🎯 Цель USE-подхода

USE позволяет:
- Диагностировать **узкие места в ресурсах**.
- Понять, **какой именно ресурс** стал ограничивающим фактором.
- Быстро локализовать проблему на уровне **железа или виртуальных ресурсов**.

## 🧠 Принцип работы

Подход USE применяется **к каждому ресурсу в системе**. Например, для CPU, памяти, дисков и сети:

```text
- Utilization: Насколько активно используется этот ресурс?
- Saturation: Есть ли очередь/ожидание доступа к ресурсу?
- Errors: Возникают ли ошибки при его использовании?
```

## 🆚 USE vs. [[RED]]

|Подход|Применение|Фокус|Метрики|
|---|---|---|---|
|USE|Инфраструктура: хосты, контейнеры, железо|Внутреннее состояние системы|Utilization, Saturation, Errors|
|RED|Уровень приложений / API|Пользовательский опыт|Rate, Errors, Duration|

## ✅ Когда использовать USE?

- При мониторинге **серверов, контейнеров, виртуальных машин**.
    
- Для выявления **узких мест на уровне ресурсов** (CPU, I/O, сеть).
    
- При настройке **системных дешбордов и алертов** по деградации хостов.
    

## 🧩 Комбинирование с другими подходами

USE хорошо сочетается с:

- **RED** — для комплексной картины "что болит" (RED) и "почему болит" (USE).
    
- **Golden Signals** — для системно-прикладного мониторинга.
    

## 📌 Заключение

USE — базовый подход для анализа и мониторинга **низкоуровневой производительности систем**. Он помогает заранее выявлять перегрузки и сбои на уровне ресурсов, прежде чем они начнут влиять на пользователей.

> Рекомендуется использовать USE везде, где есть хосты, серверы, ноды Kubernetes или bare-metal-инфраструктура.
