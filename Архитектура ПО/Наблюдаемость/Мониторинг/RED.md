# 🟥 Подход RED в мониторинге

Подход **RED** (Rate, Errors, Duration) — это метод мониторинга, ориентированный на **пользовательские метрики** микросервисов. Он позволяет быстро понять, как сервис работает с точки зрения клиента, и выявить проблемы в производительности и доступности.

## 🔧 Что такое RED?

| Компонент | Описание | Примеры метрик |
|-----------|----------|----------------|
| **Rate**  | Частота запросов к сервису. Показывает, сколько раз в секунду (или минуту) сервис обрабатывает запросы. | `http_requests_total`, `requests/sec`, `grpc_server_handled_total` |
| **Errors** | Количество или доля ошибочных запросов. Ошибки делятся на клиентские (4xx) и серверные (5xx). | `http_requests_total{status=~"5.."}`, `error_rate`, `failed_requests/sec` |
| **Duration** | Время, которое требуется для обработки запроса. Оценивается среднее, персентиль (например, 95-й) или максимальное время ответа. | `request_duration_seconds`, `latency_ms`, `response_time_95p` |

## 🎯 Цель RED-подхода

RED позволяет быстро:
- Оценить **доступность и производительность** сервиса.
- Выявить **узкие места** в работе API.
- Улучшить **наблюдаемость микросервисов** и реакцию на инциденты.

## 🧠 Принцип работы

RED ориентирован на **endpoint-ориентированную** модель мониторинга. Каждую конечную точку (например, `/api/v1/login`) следует анализировать отдельно по трём ключевым метрикам:

```text
- Rate: Насколько часто вызывается endpoint?
- Errors: Сколько из этих вызовов завершились ошибкой?
- Duration: Сколько времени занимает обработка запроса?
```

## 🆚 RED vs. [[USE]]

| Подход | Применение               | Фокус                 | Метрики                         |
| ------ | ------------------------ | --------------------- | ------------------------------- |
| RED    | Уровень приложений / API | Пользовательский опыт | Rate, Errors, Duration          |
| USE    | Уровень инфраструктуры   | Состояние ресурсов    | Utilization, Saturation, Errors |

## ✅ Когда использовать RED?

- При мониторинге **микросервисов и REST/[[gRPC]] API**.
    
- Для настройки **алертов и дешбордов**, которые показывают производительность с точки зрения пользователя.
    
- Вместе с **SLO/SLA**, чтобы понимать соответствие требованиям.
    

## 📌 Заключение

Подход RED — простой и эффективный способ наблюдения за состоянием микросервисов. Он фокусируется на том, что важно для конечного пользователя: насколько быстро, стабильно и без ошибок работает сервис.

> Рекомендуется использовать RED совместно с другими подходами (USE, Golden Signals), чтобы получить полную картину состояния системы.
