# Взаимодействие между микрофронтендами: Стратегия на основе API

## Описание

При стратегии взаимодействия на основе API каждый микрофронтенд работает как автономное приложение, получающее и отправляющее данные через общий серверный API. Это может быть REST, GraphQL, WebSocket или другой сетевой интерфейс.

Каждый микрофронтенд выполняет прямые HTTP-запросы или подписывается на поток данных через WebSocket. Состояние и связь между частями интерфейса управляются сервером, а не клиентом.

## Пример

1. Микрофронтенд `product-list` делает GET-запрос к `/api/products` для получения списка товаров.
2. Микрофронтенд `cart` обращается к `/api/cart` для отображения содержимого корзины.
3. После добавления товара `cart` отправляет POST-запрос на `/api/cart/add`, затем обновляет состояние, снова обращаясь к API.

## Преимущества

- **Независимость**: каждый микрофронтенд может быть развёрнут и обновлён независимо.
- **Чёткие границы ответственности**: бизнес-логика и состояние управляются сервером, а не браузером.
- **Масштабируемость**: взаимодействие происходит через устоявшиеся протоколы, легко масштабируется на уровне инфраструктуры.
- **Упрощённая безопасность**: аутентификация и авторизация централизованы на API-уровне.

## Недостатки

- **Задержки и переизбыточные запросы**: при сложных зависимостях между микрофронтендами возможны множественные запросы и обновления.
- **Ограниченная интерактивность**: для передачи данных между клиентами (без обновления страницы) нужен WebSocket или дополнительная синхронизация.
- **Дублирование логики**: каждый микрофронтенд может иметь похожие функции обработки состояний, приводя к дублированию кода.
- **Сложности с real-time**: без дополнительных инструментов (WebSocket, SSE) невозможна мгновенная синхронизация между микрофронтендами.

## Когда использовать

- Разные команды разрабатывают микрофронтенды независимо друг от друга.
- Компоненты интерфейса могут быть развёрнуты отдельно.
- Общая логика и состояние должны находиться на серверной стороне.
- Важно обеспечить стабильность и предсказуемость данных.

## Альтернативы и расширения

- Использование WebSocket поверх API для двусторонней связи в реальном времени.
- Применение GraphQL для сокращения количества запросов.
- Слой оркестрации данных на клиенте (например, с помощью React Query или SWR) для кэширования и синхронизации.

## Заключение

API-ориентированное взаимодействие между микрофронтендами — это надёжная и масштабируемая стратегия, особенно подходящая для распределённых команд и мультисервисной архитектуры. Однако она может потребовать дополнительной клиентской логики для эффективного управления состоянием и взаимодействием между частями интерфейса.
