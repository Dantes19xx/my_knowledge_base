## Интернирование целых чисел в Python и поведение `is`

### 📌 Кратко

Python интернирует (кеширует) целые числа в диапазоне от `-5` до `256`. Это означает, что числа в этом диапазоне **всегда ссылаются на одни и те же объекты** в памяти. Для чисел **вне диапазона** это **не гарантируется**.

---

### 📦 Что такое интернирование?

Интернирование — это оптимизация в CPython: часто используемые объекты (например, числа от -5 до 256) хранятся в памяти и переиспользуются. Это ускоряет операции и экономит память.

---

### 🧠 Пример

```python
a = 100 b = 100 print(a is b)  # True ← интернировано
```


```python
a = 1000
b = 1000 
print(a is b)  # В интерактивной среде — может быть True                
# В .py-файле — скорее всего, False
```

---

### ⚠️ Почему `a = 1000; b = 1000` может дать `True`?

- В интерактивной среде (REPL, Jupyter, ChatGPT) Python может **оптимизировать литералы**, создавая **один объект** даже вне диапазона интернирования.
    
- Это поведение зависит от контекста выполнения и **не гарантировано**.
    

---

### ✅ Как проверить интернирование надёжно

```python
a = int("1000")
b = int("1000")
print(a is b)  # False ← точно разные объекты
```

Здесь создаются **новые объекты**, а не литералы.

---

### 🧪 Надёжный тест диапазона интернирования:

```python
for i in range(-10, 270):
    a = int(str(i))
    b = int(str(i))
    if a is b:
        print(f"{i} — интернирован")
    else:
        print(f"{i} — НЕ интернирован")
```

---

### 🧩 `is` vs `==`

- `a is b` → проверяет, **один ли это объект в памяти**
    
- `a == b` → проверяет, **равны ли значения**
    

Никогда не используй `is` для сравнения чисел (и вообще примитивов), если тебе важно значение, а не объект.
