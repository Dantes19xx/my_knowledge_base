```python
a = (1, 2, [3, 4])
a[2].append(5)
print(a)
# Вывод: (1, 2, [3, 4, 5])
```


---

### ❓ Почему это работает, если `tuple` считается неизменяемым?

Кортеж (`tuple`) **неизменяемый**, но это означает, что **нельзя изменить структуру самого кортежа** — то есть нельзя:

- изменить количество элементов,
    
- заменить один элемент на другой (например, `a[0] = 99` вызовет `TypeError`).
    

Однако **если внутри кортежа находится изменяемый объект**, как список (`list`), то **этот объект всё ещё можно изменять по ссылке**.

### 🧠 Причина — поверхностная неизменяемость

В Python:

- `tuple` хранит **ссылки** на объекты.
    
- Сами ссылки (позиции в кортеже) нельзя изменить.
    
- Но **если по ссылке лежит изменяемый объект**, то он может быть модифицирован.

```python
id(a[2])  # допустим, это 123456
a[2].append(5)
id(a[2])  # всё тот же 123456 — объект остался тем же
```

### 📌 Важные примеры

```python
t = ([],)
t[0].append(1)
print(t)  # ( [1], )
```

```python
t = ([1, 2],)
t[0] += [3]  # Это работает, потому что += на списке вызывает extend
print(t)  # ([1, 2, 3], )
```

```python
t[0] = [1, 2, 3]  # TypeError: 'tuple' object does not support item assignment
```

### ⚠️ Риски

Если ты используешь кортежи как ключи в `dict` или элементы в `set`, **изменяемые элементы внутри приведут к непредсказуемому поведению**, потому что хэш будет основан на начальном состоянии.

```python
bad = ([1, 2],)
hash(bad)  # TypeError: unhashable type: 'list'
```

Кортеж — **неизменяемый контейнер**, но он может содержать **изменяемые объекты**, и они могут **меняться по ссылке**, даже если кортеж нельзя модифицировать напрямую.
