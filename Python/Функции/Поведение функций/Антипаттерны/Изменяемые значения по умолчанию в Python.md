Если в параметрах функции использовать изменяемое значение по умолчанию (например, `list`, `dict`, `set`), это значение будет сохраняться между вызовами функции. Это может привести к неожиданным результатам.

---

## ❗ Пример

```python
def extend_list(val, lst=[]):
    lst.append(val)
    return lst

list1 = extend_list(10)
list2 = extend_list(123, [])
list3 = extend_list('a')

print(list1)  # [10, 'a']
print(list2)  # [123]
print(list3)  # [10, 'a']
```


## Объяснение

- При определении функции Python **создаёт объект** по умолчанию один раз.
    
- В нашем случае `lst=[]` — это **один и тот же список**, который используется **при каждом вызове**, если параметр `lst` не передан явно.
    
- Поэтому `list1` и `list3` используют **один и тот же список**.


    

### Поведение по вызовам:

1. `extend_list(10)` — использует общий `lst`, результат: `[10]`.
    
2. `extend_list(123, [])` — передан **новый** список, результат: `[123]`.
    
3. `extend_list('a')` — снова используется общий `lst`, результат: `[10, 'a']`.

## Правильный способ

Чтобы избежать этой ошибки:

```python
def extend_list(val, lst=None):
    if lst is None:
        lst = []
    lst.append(val)
    return lst
```

Теперь при каждом вызове без `lst` будет создаваться **новый список**, и функция будет вести себя предсказуемо.


## 🧩 Почему так сделано?

- Это **оптимизация** в Python: значения по умолчанию вычисляются один раз, чтобы не пересоздавать их каждый раз.
    
- Хорошо работает с **неизменяемыми типами** (`int`, `str`, `None`, `tuple`), но **опасно** с изменяемыми.


---


> Значения параметров по умолчанию создаются один раз — в момент, когда Python интерпретирует def, даже если функция ещё ни разу не вызывалась.
> 
> Если параметр функции — изменяемый объект, заданный как значение по умолчанию, и ты его изменяешь внутри функции, то ты меняешь этот самый объект, который живёт в [[__defaults__]].  
> То есть — все будущие вызовы функции будут работать с уже изменённым объектом.
