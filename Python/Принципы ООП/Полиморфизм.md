## 📌 Полиморфизм (Polymorphism) в ООП

**Полиморфизм** — это способность одного и того же интерфейса работать с разными типами объектов.  
Название происходит от греческого: _poly_ — «много» и _morphē_ — «форма».

Суть: **один и тот же вызов может вести себя по-разному в зависимости от объекта**.

---

### 1. **Зачем нужен полиморфизм**

- **Гибкость**: код не зависит от конкретного типа объекта.
    
- **Расширяемость**: можно добавлять новые типы без изменения существующего кода.
    
- **Чистота кода**: меньше условий `if type(...) == ...`.
    

---

### 2. **Виды полиморфизма**

|Вид|Описание|Пример|
|---|---|---|
|**Ad-hoc (перегрузка)**|Один метод/оператор с разной логикой для разных типов|Оператор `+` работает для чисел и строк|
|**Параметрический**|Код работает с разными типами, не зная о них заранее|Функция, принимающая любой итерируемый объект|
|**Полиморфизм подтипов**|Использование методов через общий интерфейс (наследование)|Метод `.speak()` у `Dog` и `Cat`|
|**Интерфейсный (Duck typing)**|"Если ходит как утка и крякает как утка — значит утка"|Любой объект с методом `.speak()`|

---

### 3. **Примеры в Python**

#### 🔹 Полиморфизм через наследование

```python
class Animal:
    def speak(self):
        raise NotImplementedError

class Dog(Animal):
    def speak(self):
        print("Bark")

class Cat(Animal):
    def speak(self):
        print("Meow")

def make_it_speak(animal: Animal):
    animal.speak()

make_it_speak(Dog())  # Bark
make_it_speak(Cat())  # Meow
```

### 🔹 Полиморфизм операторов

```python
print(3 + 4)      # 7 (числа)
print("3" + "4")  # 34 (строки)
```

### 🔹 Duck typing

```python
class Duck:
    def quack(self):
        print("Quack")

class Person:
    def quack(self):
        print("I'm pretending to be a duck")

def make_it_quack(duck_like):
    duck_like.quack()

make_it_quack(Duck())    # Quack
make_it_quack(Person())  # I'm pretending to be a duck
```

Python не проверяет, **какой это класс**, главное — чтобы был нужный метод.


### 4. **Где применяется**

- В реализации интерфейсов и абстрактных классов
    
- В стратегиях (_Strategy pattern_)
    
- В обработке коллекций разных типов объектов
    
- В API и фреймворках (один метод может работать с разными источниками данных)
    

---

### 5. **Преимущества и недостатки**

✅ Преимущества:

- Универсальность и гибкость кода
    
- Уменьшение дублирования
    
- Возможность масштабирования без переписывания логики
    

⚠️ Недостатки:

- Может быть сложнее отлаживать
    
- Требует чёткого проектирования интерфейсов
