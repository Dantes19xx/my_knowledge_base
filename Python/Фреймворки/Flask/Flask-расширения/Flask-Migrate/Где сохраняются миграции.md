`flask db migrate` сам знает, куда класть файлы миграций, потому что при инициализации (`flask db init`) создаётся папка `migrations/` с настройками [[Alembic]].

---

## 📌 Как это устроено

1. Когда ты делаешь:
```bash
flask db init
```

создаётся структура:
```bash
migrations/
├── alembic.ini       # настройки alembic
├── env.py            # логика, как миграции видят твои модели
├── script.py.mako    # шаблон для новых файлов
└── versions/         # сюда будут складываться миграции
```

2. Внутри `migrations/env.py` Flask-Migrate настраивает **куда генерировать файлы** (по умолчанию — в `migrations/versions/`).

Например, там есть строчка:
```python
from app import db
target_metadata = db.metadata
```
Это говорит Alembic: _"смотри на модели из SQLAlchemy и создавай миграции на их основе"_.
    
3. Когда ты выполняешь:
```bash
flask db migrate -m "Добавил таблицу"
```

Alembic сравнивает текущие модели (`db.Model`) с тем, что есть в базе, и кладёт скрипт миграции в:

```bash
migrations/versions/<timestamp>_добавил_таблицу.py
```

---
## 📌 Можно ли изменить папку?

Да. Если тебе не нравится `migrations/`, можно:

- указать другую директорию при `init`:

```bash
flask db init --directory my_migrations
```
- или потом в командах явно указывать:
```bash
flask db migrate --directory my_migrations
flask db upgrade --directory my_migrations
```

👉 Итого:  
По умолчанию **[[Flask-Migrate]] всегда сохраняет миграции в `migrations/versions/`**, а это задаётся в конфиге Alembic (`env.py` + `script.py.mako`).
