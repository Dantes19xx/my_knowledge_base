#flask #python #фреймворки

**Flask** — это _микрофреймворк_ для веб-разработки на Python. Он создан Армином Ронахером (Armin Ronacher) и впервые вышел в 2010 году. Flask позиционируется как «легковесный каркас», который даёт базовый каркас для веб-приложения, но не навязывает структуру и дополнительные зависимости.
Для расширения функциональности фреймворка необходимо доставлять [[Flask — популярные расширения|расширения]]

📌 Ключевая идея: _«Дай минимум, но оставь возможность подключить всё, что нужно»_.

---

## Основные компоненты

1. **[[Werkzeug]]** — отвечает за HTTP-запросы, маршрутизацию и WSGI.
    
2. **[[Что такое Jinja2|Jinja2]]** — встроенный шаблонизатор для HTML.
    
3. **[[Click]]** — CLI-команды (например, `flask run`).
    
4. **[[ItsDangerous]]** — безопасная работа с сессиями и токенами.
    
5. **[[MarkupSafe]]** — экранирование HTML.
    

---

## Возможности из коробки

- Маршрутизация (`@app.route`)
    
- Работа с запросами и ответами (`request`, `response`)
    
- Поддержка middleware и хуков (`before_request`, `after_request`)
    
- Шаблоны на Jinja2
    
- Сессии (подписанные cookie)
    
- CLI для запуска и управления
    

---

## Что не входит в ядро

В отличие от «тяжёлых» фреймворков (Django, Spring), Flask не включает:

- ORM (SQLAlchemy ставится отдельно)
    
- Админку
    
- Авторизацию и аутентификацию (есть расширения `Flask-Login`, `Flask-Security`)
    
- Миграции (`Flask-Migrate`)
    
- Формы (`WTForms`, `Flask-WTF`)
    
- REST API (например, `Flask-RESTful` или `Flask-API`)
    

---

## Плюсы Flask

- Простота и минимализм — легко начать
    
- Гибкость — подключаешь только то, что нужно
    
- Отлично подходит для микросервисов и REST API
    
- Большое сообщество и множество расширений
    
- Хорош для обучения архитектуре
    

---

## Минусы Flask

- Нет единой «правильной» структуры проекта (можно запутаться без практики)
    
- Нужно самому выбирать ORM, систему миграций, средства аутентификации
    
- В больших проектах приходится писать больше инфраструктурного кода
    

---

## Когда использовать Flask

✅ Хорошо подходит:

- Для небольших сервисов и микросервисов
    
- Для REST API
    
- Для прототипов и MVP
    
- Для обучения
    

❌ Лучше взять что-то другое:

- Если нужен «всё в одном» фреймворк с админкой и ORM «из коробки» (например, Django)
    
- Если проект огромный и требует строгих стандартов
    

---

📌 Итог: **Flask — это конструктор.** Он даёт базу для веб-приложения, а остальное ты собираешь из расширений или пишешь сам. Поэтому Flask любят те, кто ценит гибкость и контроль над архитектурой.
